# 홈 작은 화면·큰 글자 검증 — 2026-10-20

사용자 승인 범위는 홈 안내의 기존 `compact` 밀도 적용이다. `width < 400` 및
`fontScale >= 1.3`일 때만 적용하며 공통 컴포넌트 기본값은 유지했다. 안내 우선순위·문구·
행동·탭·정보 묶음·버튼 위치·기본 글자 크기·장고와 배경 원본은 보존했다.

실제 `HomeScreen`, `HomeHero`, 말풍선·버튼·타입·반응형 코드를 RN Web으로 렌더링했다.
변경 전은 작업 시점 Git HEAD의 HomeHero, 변경 후는 작업 파일이다. 서버 상태·공간 선택기·
입력 시트는 고정 fixture이며 native safe area는 0이다. 글자 크기 배율은 RN Text adapter로
OS 배율과 기존 maxFontSizeMultiplier를 재현했다. 애니메이션은 reduced motion으로 고정했다.
이는 native VoiceOver/TalkBack 또는 실제 기기 검증을 대체하지 않는다.

320×640·360×640·768×1024·780×360, 배율 1·1.3·2, 정상·임박·만료·빈 재고·기한 미입력·
초기 오류·추천 생성 중·추천 완료·로딩의 9상태를 전후 216회 렌더링했다.
[108개 비교](comparison.json)에서 텍스트·버튼 접근성 이름·입력 시트 진입을 보존했고
검출된 텍스트 잘림·가로 넘침·런타임 오류는 0이었다. 화면 캡처도 직접 확인했다.

임박 안내의 높이는 320에서 배율 1.3일 때 198→156px, 배율 2일 때 348→292px로 줄었다.
배율 2의 재료 넣기 버튼 전체 노출까지 필요한 스크롤은 172.80→116.80px로 줄었다.
360에서는 각각 146→130px, 268→212px이며 배율 2의 스크롤은 56px 줄었다.
태블릿·가로 화면과 일반 배율에서는 버튼 위치 변화가 0이었다.
320 배율 1과 태블릿·가로 화면 대표 캡처는 전후 SHA-256이 동일하다.

대표 전후 PNG와 [해시 목록](screenshots.json)을 보존한다. 320·2배에서는 안내가 계속 여러 줄로
표시되며 주요 행동에 스크롤이 필요하다. 밀도 변경만으로 모든 콘텐츠가 첫 화면에 들어온다고
판정하지 않는다. 실제 기기의 큰 글자·접근성 검사는 스토어 QA 기록에 별도 남긴다.

## Android native 확인

연결된 Galaxy A34(SM-A346N)의 기존 개발 QA 앱 1.4.3(1)에서 실제 HomeHero를 실행했다.
결제·서버 흐름과 분리한 로컬 fixture다. 320·360dp, 시스템 글자 배율 1·1.3·2의
[전후 측정 12건](android-native-measurements.json)과 대표 PNG를 보존한다. 화면 크기·밀도·
글자 배율은 검사 후 원래 1080×2340·450dpi·1.15로 복원했다.

Android의 1.3 설정이 1.2999999523162842로 전달되어 초기 구현이 compact에 진입하지
않는 문제를 재현했다. 홈 조건만 소수 6자리로 정규화하고 경계 회귀 검사 9건을 추가했다.
공통 반응형·타이포그래피 동작은 변경하지 않았다. 수정 후 320dp의 안내 높이는 배율
1에서 128→128dp, 1.3에서 188→172dp, 2에서 340→222dp였다. 360dp는 각각
128→128dp, 140→124dp, 238→222dp였다. Android 비선형 글자 배율 때문에 Web
측정값과 수치가 같다고 해석하지 않는다. native 캡처에서 문구를 끝까지 확인했고 주요
행동의 콜백도 확인했다. TalkBack·VoiceOver 실제 읽기 순서와 전체 홈 서버 상태별 검증은
이 fixture 결과에 포함하지 않는다.
