# 2026-10-24~25 남은 iOS QA 결과

사용자가 기존 정리를 마친 뒤 미완료 항목도 진행하도록 명시적으로 요청했다.
새 [격리 환경](environment.json)은 빈 DB·테스트 계정 두 개로 시작한다. 기존 운영 설정과
판매 정책은 보존한다. AI 유료 호출은 추가하지 않는다.

## 현재 확인한 결과

- 실제 iPhone TestFlight 1.4.4(60)의 [월간 Sandbox 구매](ios-60-monthly-result.json)와
  [갱신](ios-60-monthly-renewal.json)을 확인했다. 갱신은 QA 공간장 재로그인 때 루트 IAP
  복구가 실제 스토어 거래를 검증한 결과이며, QA webhook 자동 수신 검증과 구분한다.
- [공유 재검증](ios-60-sharing-result.json)은 네이티브 초대 참여·개인/공유 재고 분리·캐시된
  공유 공간 재선택을 확인했다. 소유자 HTTP API로 권한을 회수한 뒤 멤버 조회는 404였고,
  동일 앱 PID에서 개인 공간으로 약 4초 안에 복귀했다. 무한 로딩은 재발하지 않았다.
  [빌드 61 재검증](ios-61-sharing-result.json)에서는 같은 흐름을 다시 확인하고, 복귀 뒤
  5개 탭의 실제 표시와 홈·설정 탭 동작도 확인해 이전 탭 표시 후속 항목을 종료했다.
- [타 계정 복원](ios-60-restore-race.json)은 서버 409·멤버 비활성을 유지했으나, 구매 이벤트와
  복원 안내가 겹치는 문제가 재현됐다. 복원 결과를 한 번에 모으고 같은 거래를 중복 처리하지
  않도록 수정했다. 추가 경계 검사까지 [복원 14개·모바일 전체 629개](validation.json)가
  통과했다. [수정 QA 빌드 61](ios-61-artifact.json)은 실제 iPhone의 1.4.4(61) 설치 후 [복원 재검증](ios-61-restore-retest.json)을 통과했다. 같은 계정은 201·성공 안내, 타 계정은 409·거부 안내 한 번이며, 각각 닫은 뒤 7초 이상 추가 안내가 없고 멤버는 계속 비활성이다.
- [가격 대조](ios-60-price-progress.json)는 미완료다. SDK storefront KOR에서 상품은 USD,
  Apple의 월간 Sandbox 확인창은 KRW 4,900을 표시했다. 원인은 확정하지 않았고 가격을
  임의 환산하거나 판매 정책을 변경하지 않았다. 빌드 61의 연간 확인창도 KRW 39,000으로,
  같은 화면 뒤 SDK 연간 USD 22.99와 차이가 재현됐다. 네이티브 가격·청구 없음 문구는
  계정 이메일이 없는 요소 캡처로 보존했다.
- [실제 구매 중단](ios-61-interrupted-purchase.json)은 Sandbox 중단 설정에서 연간 구매를
  요청하고 기기 인증 뒤 Apple의 약관 갱신 안내를 확인했다. 안내를 취소한 뒤 StoreKit 거래
  없음·서버 비활성·구매 버튼 복귀를 확인했고 중단 설정은 원래 꺼짐으로 복원했다.
  SDK의 실제 `pending` 상태는 관찰되지 않았으므로 승인 대기 통과로 처리하지 않는다.
  취소 시 영문 실패 안내가 노출되는 결함은 재현 테스트 2개 실패 후 요청 예외 경로에도
  기존 취소 처리를 적용했다. 관련 17개 테스트·전체 lint·typecheck가 통과했으며 기기 재검증은
  [실제 TestFlight 64](ios-64-cancellation-retest.json)에서 통과했다. QA 월간 구매창을 닫은 뒤
  8.682초 동안 실패 안내가 없고 구매 버튼이 복귀했다. StoreKit 활성 거래·미완료 거래와 서버
  권한이 모두 비활성이며, 다음 실제 구매창도 다시 열려 재시도를 확인했다.
- [연간 구매·환불 요청](ios-61-refund-result.json)은 실제 TestFlight 61에서 청구 없는 연간
  구매 성공 후 Apple 네이티브 환불 요청 접수와 SDK `success` 응답을 확인했다. 이후 원래
  만료 시각 전에 StoreKit 활성 거래·미완료 거래가 사라졌다. 격리 QA DB에서 같은 가상 계정의
  기존 거래 식별자를 읽기 전용으로 조회해 정상 구독 검증 API로 Apple에 재검증하자 `revoked`와
  비활성을 반환했다. 같은 앱 프로세스의 재진입 뒤 원래 구독 화면도 ‘무료 이용 중이에요’를
  표시했다. 실제 환불·수동 정상 검증·화면 반영은 통과이며, 자동 QA webhook 수신과 구분한다.
  전역 운영 알림 URL·재동기화 정책은 보존했고 DB 상태나 거래를 직접 변경하지 않았다.
- iOS SDK가 실제 StoreKit 승인 대기를 `deferred-payment` 오류로 전달하는 경로도 기존
  ‘결제가 확인 중이에요’ 안내로 처리하도록 최소 수정했다. 요청 거부와 오류 이벤트가 함께 와도
  안내가 한 번만 표시되고 권한 부여·거래 완료·구매 의도 삭제를 하지 않는 관련 21개 테스트가
  통과했다. [실제 TestFlight 64 승인 대기](ios-64-pending-result.json)도 확인했다. Apple의
  ‘허락 요청’ 뒤 기존 안내가 한 번 표시됐고, 닫은 뒤 약 8.7초 동안 추가 안내가 없으며 구매
  버튼이 복귀했다. 활성 월간 거래와 서버 권한은 없었다. 이전에 환불한 연간 거래가 철회 날짜와
  함께 미완료 목록에 재전달된 것은 이 월간 대기와 구분해 기록했다. 원본 SDK는 보존하며 격리 QA 빌드에만
  [Apple의 Sandbox Ask to Buy 옵션](https://developer.apple.com/documentation/storekit/product/purchaseoption/simulatesasktobuyinsandbox(_:))을 추가한다.
  Apple Sandbox는 대기 시작을 지원하지만 승인·거절로 대기를 해소하는 시나리오는
  [Xcode에서만 지원](https://developer.apple.com/documentation/storekit/testing-at-all-stages-of-development-with-xcode-and-the-sandbox)하므로 결과 범위를 구분한다.

[월간 만료 관찰](ios-61-monthly-expiry.json)은 미완료다. 서버 캐시는 만료·앱은 무료였지만 일반 미디어 로그인 뒤 storefront가 USA였고, QA Sandbox로 돌아오자 나중 갱신이 복구됐다. 같은 Sandbox 구독의 자연 만료로 인정하지 않는다.
[월간 명시적 취소](ios-61-monthly-cancellation.json)는 네이티브 취소 확인과 같은 계정 복원 뒤 서버 `willRenew=false`를 확인했다. [취소 기간의 만료](ios-61-canceled-term-expiry.json)는 동일 Sandbox 테스터·StoreKit·서버·앱 화면 대조를 통과했다. [실제 iOS 푸시](ios-61-push-result.json)는 정상 스케줄러 수신과 공유→개인 보관함 탭 이동을 통과했다. 환불은 위의 수동 Apple 재검증 경로로, 승인 대기 진입은 빌드 64에서 확인했다. 가격 일관성과 자동 QA webhook 수신은 통과하지 않았다.
기기 인증·Apple 처리 대기만으로 통과를 기록하지 않는다. 전체 lint·typecheck·docs 검사가 통과했다. 원본 작업 파일을 보호한 격리 복사본에서 취소·승인 대기 안내 수정 후 전체 테스트 1,457개가 통과했다. 기본 실행에서 제외되는 DB 6개는 최종 소스로 [새 로컬 PostgreSQL 검증](strict-integration-final-result.json)을 다시 실행했다. migration 45개 적용 뒤 6개 모두 건너뜀 없이 통과했고 임시 DB·프로세스·자격증명은 제거했다. 이전 별도 SNS 파일 lint 실패 기록은 이력으로 남겼으며 해당 파일을 수정하지 않았다.

이번 재개의 절대 종료는 **2026-10-25 15:59 KST**다. 기존 QA를 포함한 Railway 누적
$7 또는 사용량 미확정 시 해당 QA 프로젝트를 정리한다. 총 승인 예산 $10은 늘리지 않는다.

추가했다. 이 장치는 Mac·인증이 끊겨도 프로세스를 중지하지만 볼륨 삭제를 대신하지 않으므로
프로젝트 삭제는 별도로 확인한다. 기존 72시간 내 삭제 실패 이력은 이전 기록에 유지한다.

Sandbox 환불 요청 도구를 추가했다. 이 도구는 QA 플래그·preview·정확한 QA 주소·가상 계정으로

## iOS 제어 연결 복구

[빌드 61 체크포인트](ios-61-progress-checkpoint.json)에 실제 완료·남은 항목과 복원할 설정을 기록했다.
취소 기간 종료 뒤 [서버 재확인](ios-61-expiry-api-resume.json)에서는 `expired`·`willRenew=false`를 확인했고
멤버는 계속 비활성이다. 당시 미완료였던 같은 Sandbox의 최종 기기 화면 대조는 아래 재연결 후 통과했다.
[권한 거부 안내](ios-61-push-denied.png)와 [권한 허용·토큰 등록](ios-61-push-registered.png)은 확인했다.
당시 수신 감시 중 XCTest 연결이 종료돼 발송 예정 전에 QA 알림을 다시 껐으며 그 시도는 수신·탭 통과로 처리하지 않았다. 아래 재연결 후 별도 정상 스케줄러 시도로 실제 수신·탭을 확인했다.

10월 25일 iPhone의 USB 재연결·잠금 해제를 확인했다. 이전 자동 승인 검토 시간 초과로 실행되지
않았던 보조 앱 재시작은 재시도했으나, XCTest가 자동화 모드 활성화 시간 초과로 초기화에 실패했다.
기존 서명·보조 앱을 재사용했고 새 프로필·키를 만들지 않았다. 사용자가 미러링 전환을
명시적으로 승인하고 iPhone을 잠근 뒤 미러링 화면이 연결됐다. 이전 전환 조건에 따른 승인
차단은 해소됐다. 다만 터치 입력은 `noWindowsAvailable`로 실패했고, 창 조회 오류·시간 초과 뒤
도구 세션 초기화로 화면 조회와 키보드 입력만 복구됐다. USB 조회에서 남아 있는 QA 보조
앱 프로세스는 없었다. 이는 제어 도구의 오류이며 새로운 앱 시나리오 통과로 기록하지 않는다.
사용자가 원래 꺼져 있던 ‘전체 키보드 접근’을 임시로 켰으나, 미러링에서 Tab은 버튼 이동이
아닌 문자 입력으로 전달돼 키보드 경로도 사용할 수 없었다. 설정을 다시 끄고 기기를 재시작한
뒤 USB 잠금 해제를 요청했다. 사용자가 전체 키보드 접근을 끄고 기기를 재시작한 뒤, 미러링
프로세스 종료·실제 잠금 해제를 확인해 기존 보조 앱을 실행했다. 사용자 완료 신호 뒤 약 1.3초
안에 실행을 시작했고 약 53초 뒤 WDA 연결이 복구됐다. 네이티브 설정에서도 전체 키보드 접근의
원래 꺼짐 상태를 확인했다.

[취소된 기간의 만료 대조](ios-61-canceled-term-expiry.json)에서는 KOR storefront의 StoreKit 활성
거래·미완료 거래가 모두 없고, 서버 비활성·앱 ‘무료 이용 중’을 확인했다. 네이티브 설정에서도 동일
QA Sandbox 테스터가 로그인돼 있음을 확인해 취소 기간 만료 대조를 통과했다. USD 상품 가격은 기기 재시작 뒤에도 재현됐다.
공유 공간을 보고 있던 앱을 백그라운드에 둔 뒤, 개인 공간 재료의 실제 알림을 10월 25일
11:47 KST 정상 서버 스케줄러로 예약했다. 초기 배너 관찰에서는 찾지 못했으나, 11:53 KST
알림 센터에서 실제 QA 알림을 확인하고 직접 탭했다. 동일 앱 PID에서 개인 보관함·해당 재료로
이동했으며 5개 탭도 표시됐다. 수신 증거는 다른 앱 알림을 제외한 네이티브 알림 요소 캡처로
보존했다. QA 알림 설정은 다시 껐으며 정확한 전송 도착 시각·배너 표시는 통과로 주장하지 않는다.

기존 QA 절대 종료·누적 비용 한도는 연장하지 않으며 추가 유료 AI 호출은 하지 않는다.
