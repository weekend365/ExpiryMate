  작은 크기의 `adaptive` 기본 동작에 맡기면 좁은 화면에서 말풍선 방향이 바뀌기 때문이다.

  API·공유 계약·앱 버전·배포 설정 변경은 없다.

## 검증 방식과 한계

React Native Web에서 작업 전 소스와 변경 소스를 비교한다. 설정·첫 시작은 실제 route,
홈·장보기는 실제 feature 컴포넌트다. 추천·등록 완료는 route의 실제 carousel JSX와
스타일, 직접 등록·조리는 route의 실제 `StepFlow` 여는 JSX를 추출해 예시 데이터와
검토용 입력·본문·푸터로 조합한다. 크기·배치 표현식은 화면 코드에서 가져온다.
전체 앱의 로그인·서버 저장·요리 실행 화면을 재현하는 fixture는 아니다.

Pretendard 5종을 마운트 전에 로드하고 기존 이미지와 실제 `Mascot`·말풍선·carousel·
`StepFlow`·`Screen`·`Button`을 사용한다. 글자 배율·상한은 Web 어댑터로 재현한다.
라우터·앱 상태·구독·아이콘·모션·safe area는 대역이다. 동작 줄이기는 켠 상태다.
직접 등록의 키보드 상태는 props와 480 높이의 뷰포트로 재현하며 실제 OS 키보드가 아니다.

대상은 홈·추천·장보기·설정·첫 시작·등록 첫 안내·키보드 표시·다음 입력 단계·등록 완료·
조리 진행·조리 완료 11개 상태, 320·360·780 폭 × 글자 1·1.3·2배다.
전후 DOM 측정, 장고 크기·말풍선 방향·가로 넘침·버튼 동작·스크롤 접근을 기록한다.
