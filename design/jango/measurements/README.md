# 추가 제작 포즈 수치 검증

대상은 `empty`, `worry`, `speak`, `point`, `icon-crop`의 1254px 원본이다.
키트 6종의 기존 수치·검수 주장은 `../kit-v3/manifest.json`에 그대로 보존한다.
이번 기록을 키트 원본의 측정 결과로 간주하거나, 반대로 키트 측정을 추가 원화의 승인 근거로 사용하지 않는다.

- [inputs.json](./inputs.json): 원본 경로·SHA-256, 원본 크기, 시각적으로 선택한 ROI, 표정 분류, 관찰일과 오차.
- [report.md](./report.md): 실제 값·BIBLE 범위·최종 판정과 포즈별 검수 이미지 링크.
- [results.json](./results.json): 원본·입력·BIBLE·측정 코드 해시, 외곽 추출점, 좌표축, 표정 경계·중심·크기, 항목별 판단 근거.
- `overlays/`: 원본의 복사본에 측정 영역과 결과를 겹쳐 그린 진단 이미지. 제작 에셋이나 런타임 파일이 아니다.

## 실행

```sh
pnpm --filter @expirymate/mobile mascot:measure
pnpm --filter @expirymate/mobile mascot:anatomy:audit
```

`measure`는 결과와 검수 이미지만 생성한다. 미달 원화를 고치거나 승인하지 않는다.
`anatomy:audit`는 파일을 쓰지 않고 다시 측정한다. 대상 누락·중복, 원본/manifest 불일치,
오래된 결과·검수 이미지, `fail` 또는 `needs-review`가 하나라도 있으면 종료 코드 1이다.
기존 `mascot:audit`는 파생 파일 검사를 모두 실행한 뒤 이 검사를 실행한다.

## 측정 방법

측정 구현은 `apps/mobile/scripts/mascot-anatomy.mjs`의 `outer-door-roi-v1`이다.
외부 키트의 `work/` 도구나 개인 절대 경로, Python·새 패키지에 의존하지 않는다.

1. 원본 PNG의 RGBA 픽셀을 그대로 읽는다. 얼굴 문 외곽의 상·하·좌·우를 관찰해 선택한
   영역에서 `alpha > 220`, `max(R,G,B) < 100`인 선 픽셀을 찾는다.
   각 스캔선의 가장 바깥 픽셀을 선택하므로 문 안쪽 밝은 영역이나 이중선의 안쪽을 측정하지 않는다.
   손잡이·경첩·모자와 손이 겹치는 곳은 외곽 선택 영역에서 제외한다.
2. 문 하단 중앙의 외곽 픽셀에 직선을 맞춰 좌표축 각도를 구한다. 눈은 축 결정에 쓰지 않는다.
   모든 측정 좌표만 이 축으로 투영하며 원본 이미지를 회전·리샘플링하지 않는다.
   외곽 폭·높이는 선택한 네 변의 투영 극값 차이이고, 표정 중심은 외접 상자의 중심이다.
3. 각 눈·입은 별도 ROI의 가장 큰 4-연결 어두운 성분을 사용한다. 볼터치는
   `alpha > 220`, R=175–225, G=200–240, B=180–225, G−R≥8, G−B≥5인 연한 민트 성분을 사용한다.
   민트 장갑이나 땀방울을 볼터치로 측정하지 않도록 영역을 따로 지정한다.
4. 16픽셀 미만, 유의한 복수 성분, 표정의 ROI 경계 접촉, 주석에 기록된 가림은 `needs-review`다.
   외곽 자체의 ROI 잘림이나 검출 불능은 입력 오류로 명령을 중단한다. 영역을 다시 확인해야 한다.
5. `empty`는 무기력 표정 중 작은 처진 입을 선택했으므로 슬픔의 처진 입 폭 0.09–0.13W를 사용한다.
   그 곡선의 높이는 BIBLE에 수치 범위가 없어 실측 높이만 남기고 임의의 통과 범위를 만들지 않는다.
   아이콘의 오른눈만 윙크의 감은 눈 범위를 사용하고, 나머지는 해당 감정의 타원 눈 범위를 사용한다.

## 오차와 판정의 의미

BIBLE의 1024px MASTER 관찰 오차 약 ±3px를 원본 1254px에서 ±3.673828125px로 환산한다.
두 좌표의 차이인 치수·상대 위치에는 ±2배를 적용하고 분모의 변화도 함께 계산한다.
이는 **보수적 좌표 오차 구간**이며 통계적 신뢰구간이 아니다. BIBLE 허용 범위는 변경하지 않는다.

- `nominalStatus`: 계산한 실측값 자체가 BIBLE 수치 범위 안인지 표시한다.
- `pass`: 오차 구간 전체가 허용 범위 안이며 관찰 문제가 없다.
- `fail`: 오차 구간 전체가 허용 범위 밖이다.
- `needs-review`: 오차 구간이 경계에 걸리거나 가림·검출 모호성이 있다. 정상 또는 실패로 단정하지 않는다.

정면에 가까운 래스터 문 외곽을 네 변으로 근사하는 방식이다. 측면의 원근을 복원하거나,
손가락 구조·모자 볼륨·선화의 의미를 자동 판정하지 않는다. 그 항목은 별도 시각 검수다.
오차가 표정의 작은 허용 범위보다 클 수 있으므로 명목상 범위 안이어도 재검토로 남을 수 있다.
통과 항목 수를 늘리려고 ROI를 표정에 맞춰 옮기거나 오차·기준 범위를 조정하면 안 된다.

## 현재 결과와 후속 처리

아이콘은 얼굴 폭/높이 약 **1.3611**(허용 1.2544–1.3056)과 윙크 눈 폭에서 명확한 미달이다.
나머지 4종도 경계값의 불확실성이 있어 전체 통과로 승인하지 않는다. 구체적인 값은 생성 보고서를 따른다.
요청에 따라 원화·앱 마스터·런타임·브랜딩·스토어 이미지를 변경하지 않는다.
후속 작업은 재검토 항목의 더 정밀한 측정과 미달 원화 수정이며, 현재 검사 실패를 기준 완화로 숨기지 않는다.
