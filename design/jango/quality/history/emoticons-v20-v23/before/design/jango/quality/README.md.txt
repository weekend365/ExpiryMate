# 장고 준비·검수·최종 출력

[v18 활성 MASTER](../style-master.json), [원본 32종 목록](../master-set.json), [BIBLE](../reference/JANGO-CHARACTER-BIBLE.md), [스타일 가이드](../reference/JANGO-STYLE-GUIDE.md)가 역할별 정본이다. [복원과 v21 규칙 반영 범위](../reference/STYLE-MASTER-ADOPTION.md)를 따른다. 정책 v7의 CLI는 v18 원본의 무결성·기존 입 측정과 `emoticon`·`style-reference` 후보의 준비·검수·서명 출시를 지원한다. 신규 준비의 기본/허용 스타일은 `handdrawn-crayon`이며 `colored-pencil`은 v19 과거 감사 전용이다. 이모티콘·SNS 표현 확장의 허용·검토 기준은 BIBLE에 둔다. 기존 자동 입 검사의 분류·임계값·제출 규격·서명 조건은 유지한다.

## 현행 이모티콘·스타일 참조 후보 준비

`jango:prepare id input request [mouthMode] [reason] [expression.json]` 위치 인자와 `--style`·`--kind`·`--composition`·`--panel` 옵션을 유지한다. 구성 옵션은 등록된 v18 보드와 1–32 번호를 함께 사용한다.

```sh
pnpm jango:prepare 01-v18-derived design/jango/emoticons/kakao-32/v18/source-originals/01-r2.png '손인사 동작 변경' speak-open '먼저 인사' --style handdrawn-crayon --kind emoticon --composition design/jango/reference/v18-composition.png --panel 1
```

기존 입 자동 판정은 idle-u·speak-open·neutral-line·sad-arc를 지원한다. 이모티콘·SNS 전체의 입 표현을 제한하는 목록은 아니다. 기본 외 모드는 선택 이유가 필요하다. 표정 JSON은 family·intensity(1–3)·eyes·brows·pose를 기록한다. 실제 참조는 v18 MASTER 또는 생성·재사용 계보가 연결된 파생 후보여야 한다. 등록되지 않은 파일·변조·삭제된 파일·순환 계보는 거부한다.

형태·그림체 대표는 v18 24번이며, 기본 입 구조는 09/01/11/17번, 동작은 해당 원화를 첨부한다. 원본 32종의 선·색·질감을 우선한다. 새 앱 작화와 문구 포함 이모티콘은 모자부터 두 신발까지 전신을 기본으로 하며 원본의 하반신 생략은 전신 원화를 참고한 별도 후보로 확장한다. 자연스러운 가림과 화면 밖 신체 크롭을 구분한다. v19 장면은 과거 참조이며 신규 기본 스타일이나 투명 캐릭터 edit-target으로 사용하지 않는다. 동일 파일을 한 번만 첨부하고 실제 배열 기준 imageIndex를 기록한다. 최대 5개, 입 확대는 진단 자료로 구분한다. 준비 기록을 덮어쓰지 않는다.

## 사용자 지정 표현 확장 후보

2026-10-15 사용자의 선호 확인과 규칙 수정 요청에 따라 [v21에서 반영한 기준](../reference/STYLE-MASTER-ADOPTION.md)을 BIBLE의 이모티콘 표현 확장에 적용한다. [v21 개선안](../emoticons/kakao-32/v21/creative-brief.json)은 사례다. 후속 후보도 해당 범위에서 감정에 맞는 눈·입·얼굴 배치와 포즈를 설계할 수 있다. 준비 기록에는 해당 작업의 요청과 이 규칙 반영 근거를 참조하고 컷별 의도를 구체화한다. 허용된 표현마다 별도의 재허가를 요구하지 않는다. 이 범위를 활성 MASTER 전체의 변경이나 서명된 출시로 해석하지 않는다.

`jango:prepare`의 선택적 `--creative-brief <버전>/creative-intents/<번호>.json`은 `expressive-custom` 모드·표정 설계와 함께 사용한다. 제작 전에 사용자 요청 근거·의도·보존 정체성·허용 변형·기존 입 참조의 맥락을 기록하고 해시로 묶는다. 첨부 입 원화는 과거 표현 맥락이며 새 입의 형태 고정 지시가 아니다. 기록 변조·누락과 기존 모드로의 오분류를 거부한다. 이 경로의 입 검사는 측정값만 제공하고 항상 `needs-review`를 반환하며 `jango:promote`는 거부한다. 입의 원본 픽셀·ROI·임계값을 조작해 통과시키지 않는다.

레터링·문구는 [스타일 가이드](../reference/JANGO-STYLE-GUIDE.md)의 서체 비교·공통 글자 크기·감정별 배치를 따른다. 신규 조판은 문구마다 잉크 높이를 같게 만드는 대신 기준 문장을 공유해 음절별 확대율 차이를 막는다. 측정 레터링은 ±10도 범위의 회전을 지원하지만 수평과 소수 ±3도 강조를 기본으로 한다. 크기·흰 외곽선 적용 후 premultiplied-alpha 방식으로 회전하며 바깥 여백·문구와 그림의 충돌을 다시 검사한다. 기존 출력 재현 경로는 유지한다. 문구를 가린 감정 구분과 80·120px 밝고 어두운 배경의 읽힘을 별도 관찰한다.

## SNS 카툰의 준비·검토·재사용

연재 제작의 활성 사례는 [승인 v6 레지스트리](../cartoon-series.json)다.
[카툰 제작 정본](../reference/SNS-CARTOON-GUIDE.md)의 참조 선택·생성 지시문·원본/360px 검수표를
아래 절차와 함께 사용한다. v18 원본은 캐릭터 MASTER로 유지한다. v1/v2 단순 콜라주와 과거 회차 프롬프트를
현재 기본값으로 되살리지 않으며 승인된 v6의 등장인물·줄거리·구도를 모든 회차에 고정하지 않는다.

SNS는 MASTER를 보존하면서 BIBLE의 표현 확장 기준으로 별도 파생본을 제작할 수 있다. 현재 `jango:prepare`에는 SNS 전용 종류가 없고, SNS 전용 등록·검사·출력 CLI도 없다. 이모티콘용 `expressive-custom`을 SNS 검수 지원으로 해석하거나 기존 `emoticon`·`style-reference` 종류나 네 입 모드로 거짓 분류해 SNS 변형을 통과시키지 않는다. 도구 미지원은 창작 금지가 아니며 아래 제작·검토 기록을 별도로 남긴다.

1. **제작 전:** 고유 후보 ID와 `SNS 카툰` 용도, v18 원본 MASTER까지 이어지는 입력 경로·해시, 그림체·형태·동작·입의 실제 참조, 바꿀 영역·목적·방법을 기록한다. 새 입은 기본 입과의 차이와 원하는 감정을 설명한다. 생성·편집 시 실제 첨부 참조와 해시를 기록하며, 생성 없이 합성했다면 그 사실과 변환·레이어 정보를 기록한다.
2. **후보 제작:** 원본을 덮어쓰지 않고 별도 파일로 만든다. 단순 합성 가능한 변경은 오프라인 처리를 우선하고, 새 작화·편집이 필요한 변경을 구분한다. 기존 준비·생성 기록을 소급 작성하거나 덮어쓰지 않는다.
3. **비교 검토:** 원본과 후보를 함께 보며 BIBLE의 변형별 기준으로 구조 연결·가림·원근, 활성 v18의 크레파스 선·불투명 색면·약한 종이 결, 편집 이음새, 캐릭터 인지·감정·컷 간 일관성을 확인한다. 좌우 반전은 구조 변화와 보정 여부를 기록한다. 불확실한 부분은 재검토로 남긴다.
4. **사용자 채택:** 보정·재검토 후 사용자의 명시적 SNS 채택 근거, 대상 파일 해시·용도·사용 범위를 기록한다. 에이전트의 자동 검사나 이번 정책 변경을 개별 후보의 채택으로 대신하지 않는다.
5. **재사용:** 채택된 파일과 기록을 ID로 참조한다. 재변형은 새 후보로 검토한다. 앱 반영·MASTER 승격·서명된 이모티콘 출시는 각각 별도 절차다.

`jango:check` 통과는 SNS 파생물의 검수·채택을 증명하지 않는다. 검사 대상 밖에 파일을 두었다는 이유로 승인된 것으로 취급하지 않는다. 현행 이모티콘 관문 밖의 SNS 출력은 위 사용자의 SNS 채택·사용 범위 기록에 근거하며, `releases.json`이나 출시 서명을 생성·대체하지 않는다. 추후 SNS 도구를 추가할 때 이 기록·미채택 거부·출시 경계의 검증을 함께 구현한다.

## MASTER와 후보

v18 32종은 사용자가 다시 지정한 활성 MASTER이며 불변 원본·포즈 레지스트리다. v19의 과거 채택과 구분한다. 새 준비를 소급 작성한 생성 후보가 아니다. 종료된 제작 기록은 history/v18-creation에 원문으로 보존하며 과거 이미지가 삭제되었음을 명시한다. 이력 속 경로는 활성 입력이 아니다.

`jango:audit v18-01`부터 `v18-32`까지 현재 정책으로 재측정할 수 있다. preparation은 master-adoption으로 명시한다. 과거 9종 재검토와 현재 입 측정을 별도 표시한다. MASTER 해시 변경을 자동 수용하지 않는다.

새 이모티콘 결과는 활성 v18 크레파스 표현으로 별도 파생 버전에 개별 준비·생성 기록과 후보를 만든다. `record-jango-image.mjs <번호-v버전[-시도]> <실제 생성 파일>`로 도구 출력 바이트를 보존하고 `build-jango-emoticons.mjs --base=...`로 조립한다. v18 원화·스티커·레터링은 덮어쓰지 않는다. SNS 제작 기록을 이모티콘 생성·준비 기록으로 대신하지 않는다.

원화 재사용은 준비 후 `pnpm jango:reuse <번호-v버전[-시도]>`로 원본 바이트를 복사한다. 이 작업은 이미지 생성을 실행하지 않으며 `derivation-records`에 원본 경로·해시·준비 기록·실제 입력을 남긴다. AI 작화의 `generation-records`와 구분하며, 등록·계보 검사는 누락·변조·생성 이력 오표기·순환 참조를 거부한다. 원본과 같은 입 좌표·기울기·재검토 상태를 보존한다.

전신 파생은 `layout.framing: "full-body"`를 사용하고 신체 크롭을 허용하지 않는다. 선택적 레터링 `inkHeight`·`outlinePx`·`punctuationScale`은 1024px 조립 좌표를 사용한다. 신규 `sizeBasis: "font-reference"`와 `referenceText`를 지정하면 `inkHeight`는 **기준 문장**의 목표 잉크 높이이며 개별 문구의 실제 높이가 아니다. 같은 기준 래스터·확대율을 공유하고 폭 초과를 거부한다. `inkStrokePercent`(0–3)는 이 모드에서만 허용하는 선택적 진한 획 보강이며 CoreText 글자 크기 대비 퍼센트다. 보정 래스터·폰트·해시·실제 높이·유효 글자 크기를 기록한다. `outlinePx`는 흰 외곽선 픽셀, `punctuationScale`은 말줄임표 비율이다. `pnpm jango:lettering <버전 경로>` 후 `jango:build --base=<버전 경로>`로 조립한다. 새 옵션을 생략한 과거 잉크 높이 정규화·JXA 출력 경로와 v18 원본은 유지한다. 이 출력은 검토 후보이며 최종 서명·출시를 뜻하지 않는다.

## 현재 선택한 이모티콘 최종 디자인

2026-10-20 사용자의 최종 버전 정리 요청에 따라 [v24 최종 32종](../emoticons/kakao-32/v24/README.md)을 구성했다. v22의 31종과 v23의 새 29번 ‘지쳤어...’를 합쳤으며, 원화·레터링·배치·최종 PNG 바이트는 선택본과 같다. [현재 포인터](../emoticons/kakao-32/current.json)와 [전체 출처 목록](../emoticons/kakao-32/v24/collection.json)을 정본으로 확인한다. v18 캐릭터 MASTER와 앱 자산은 유지한다.

`pnpm jango:final:build`는 공식 준비·재사용·조립·등록 경로로 새 이미지 생성 없이 묶음을 만들고, `pnpm jango:final:check`는 선택본·현재 포인터·전체 파일 목록·원본 계보·입 검사와 좌표의 승계·기존 자산 보존을 대조한다. 원본은 독립 파일로 복사하고 지원하는 파일시스템에서 복사 시점의 저장 공간을 공유한다. 출처 경로를 바꾸는 심볼릭 링크는 쓰지 않는다. 기존 버전은 [제작 이력 안내](../emoticons/kakao-32/history/README.md)에서 구분하며 준비·출처 해시가 가리키는 물리 경로를 보존한다.

여기서 ‘최종’은 사용자가 선택한 이모티콘 디자인의 정리 범위다. 기존 AI 제작 이력·입 재검토·서명된 출시 조건은 그대로 유지한다. `releases.json`과 `jango:promote`·`jango:export`를 대신하지 않는다.

## 재생성 가능한 중간 파일 정리

2026-10-20 사용자 요청에 따라 v20–v23의 미사용 중앙 정렬 `characters` 캐시 97개, 개별 `thumbs` 97개, 중복 `preview-120.png` 3개를 정리했다. 원화·최종 스티커·동일 배치의 문구 없는 이미지·갤러리에서 사용하는 크기별 비교 자료·제작 출처·검수 이력은 보존한다. v18 MASTER와 앱 자산은 변경하지 않는다.

[정리 기록](cleanup/20261020.json)은 각 삭제 파일의 원래 SHA-256·바이트 수·재현 방법·보존한 입력 해시를 남긴다. `pnpm jango:cleanup`은 이 기록과 실제 입력으로 삭제된 PNG의 바이트를 메모리에서 재현해 검증한다. 과거 보존 스냅샷은 수정하지 않으며, 그 안의 삭제된 중간 파일도 재현한 해시를 당시 해시와 대조한다. 원화·출처·출시 검사의 물리 파일 요구는 그대로 유지한다.

기본 `jango:build`는 이 세 종류의 미사용 캐시를 생성하지 않는다. 과거 출력을 별도 후보 경로에서 재현할 때만 `--keep-intermediates`를 지정한다. 검토용 밝고 어두운 미리보기와 80·120·360px 비교 자료는 계속 제공한다.

## 기존 검사와 이모티콘 출시

- jango:reports:refresh는 현재 증거만 재계산한다. 서명·준비·채택을 생성하지 않는다.
- jango:check는 활성 v18 MASTER·레지스트리와 원본 바이트 및 v19 역사적 채택 무결성, 보고서 최신성, 지원하는 후보 종류의 미등록 이미지, 서명된 출시 목록을 검사한다. 종료 이력은 활성 후보 검사에서 제외한다. SNS 전체를 검사하는 명령은 아니다.
- 입 검사의 임계값·채움·연결·닫힌 영역·곡률·혀 기준은 유지한다. 기준 원화는 v18 입 구조 참조를 유지한다. 다른 장면에서 임의 ROI를 따서 통과 기준으로 바꾸지 않는다. 그림체·질감의 품질은 별도 시각 검사이며 기존 보수적 입 검사의 불확실성을 숨기지 않는다.
- 가림·질감 불확실성·25도 초과 기울기는 재검토다. 원화 ROI를 거짓으로 바꾸지 않는다.
- 360px·최소 8px 여백·투명 가장자리·원화 잘림·문구 충돌을 검사한다. 작은 출력과 감정 구분은 별도 시각 관찰이다.

`jango:promote <id> <signed-review.json>`와 `jango:export`는 기술·입 검사 통과와 JANGO_REVIEW_PUBLIC_KEY로 검증한 Ed25519 외부 서명을 요구한다. 사용자 MASTER 채택이나 앱 사용 지시를 출시 서명으로 대신하지 않는다. 에이전트는 서명이나 검수용 개인키를 만들지 않는다.

서명 payload는 `{binding, decision:"approved", reviewer, reviewedAt, checks}`이며 rules.json의 공통·스타일 시각 검사 전 항목이 true여야 한다. 내용 변경은 binding을 변경해 이전 서명을 무효화한다. `releases.json`만 승인된 이모티콘 출력 목록이다.

v18 MASTER 복원은 앱 PNG 교체·32종 재작화·입 재검토 해결·외부 서명을 뜻하지 않는다. 보고서는 active-v18-original 범위로 갱신하되 mouth/technical/기존 재검토 결과를 보존한다. 정책 v5·v6 파생 계보는 파일·해시가 온전할 때 참조로 읽을 수 있지만, 과거 준비를 v7 신규 준비로 통과시키지 않는다. 중단한 v19 앱 후보는 활성 입력에서 제외하고 결정·생성 해시를 종료 이력에 남긴다.

정본 문서나 관문 설명이 바뀌면 보고서의 context·binding도 바뀐다. `jango:reports:refresh`로 현재 증거를 갱신하되 MASTER·기존 측정과 재검토 상태·과거 준비·채택·서명 이력은 보존한다. 당시 문서 해시로 묶인 후보의 현재 preparation이 `stale`로 바뀌면 그 상태를 기록하며 과거 준비·생성 기록이나 제작 당시 검수 보고서를 새 문서 해시로 덮어쓰지 않는다. 새 제작은 새 준비 기록을 사용한다. 갱신된 보고서를 새로운 승인으로 해석하지 않는다.

BIBLE을 수정하면 앱 원화 관찰 보고서의 문서 해시도 달라진다. `pnpm --filter @expirymate/mobile mascot:measure`로 현재 관찰 보고서를 재계산하고, 문서만 바꾼 경우 원본·ROI·측정값·재검토 상태·비교 이미지가 그대로인지 대조한다. `mascot:anatomy:audit`와 관련 테스트로 보고서의 재현성을 확인한다. 문서 해시 갱신을 위해 앱 자산을 교체하지 않는다.
