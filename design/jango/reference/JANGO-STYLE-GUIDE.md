# 장고 STYLE GUIDE — v18 원본 MASTER

[BIBLE](./JANGO-CHARACTER-BIBLE.md), [v18 활성 MASTER](../style-master.json), [채택·규칙 반영 범위](./STYLE-MASTER-ADOPTION.md)와 [MASTER 목록](../master-set.json)을 따른다. 모든 신규 장고 제작은 [source-originals 32종](../emoticons/kakao-32/v18/source-originals)에서 출발하며 파생본도 MASTER까지의 계보를 보존한다. 기본 대표는 24번이다. v19 교체 작업은 중단했으며 기존 앱 에셋은 유지한다. MASTER 보존, 기본형 재현, v21에서 반영한 생활 친구 성격과 이모티콘·SNS 표현 확장의 적용 범위는 BIBLE을 따른다.

## 제작

- 필요한 v18 원화 또는 출처·사용 범위가 기록된 파생본을 선택한다. 원본 파일은 보존하며 창작 변형은 매체별 허용 범위의 별도 후보에 적용한다. 이모티콘·스타일 참조 후보는 `jango:prepare`, SNS는 [검수 안내](../quality/README.md)의 매체별 준비를 따른다. 표현 확장 이모티콘은 `--creative-brief` 경로를 사용한다.
- 형태·그림체 대표와 동작 원화, 선택 입 참조를 역할별로 첨부한다. 같은 파일은 한 번만 첨부하고 최대 5개를 지킨다.
- 기본형은 크레파스의 단일 윤곽, 불투명 색면, 민트·차콜·살구 볼터치, 약한 질감과 진한 표정을 유지한다. 이모티콘·SNS의 변형은 BIBLE의 각 표현 확장 기준으로 구조·질감·캐릭터 인지를 검토한다.
- 새 앱 작화와 문구 포함 이모티콘은 전신을 기본으로 한다. 하반신이 생략된 MASTER는 원본 그대로 보존하고, 확장은 전신 원화의 구조·비율을 따른 별도 후보로 만든다. 공간이 부족하면 문구를 먼저 조정한다. 이불·자세의 자연스러운 가림과 SNS의 의도한 장면 프레이밍은 신체의 우발적 잘림과 구분한다.
- 좋은 원화는 재사용한다. 배치·레터링만 바꾸는 작업을 AI 재생성으로 기록하지 않으며, 실제 새 작화와 생성 없는 파생의 입력·해시·작업 방법을 구분한다.

## 작은 출력과 글자

SNS의 레터링·장면 연출·모바일 검수는 [승인 v6 제작 기준](./SNS-CARTOON-GUIDE.md)을 따른다. 캐릭터 MASTER와 구분된 매체 기준이며 앱·이모티콘의 말풍선·글꼴·출력 규격을 바꾸지 않는다.

- 얼굴 폭 48px 미만에서는 미세 입자·봉제선보다 표정과 구조선의 읽힘이 우선이다. 단순 크기 파생 과정에서 얼굴을 몰래 다시 그리지 않는다. SNS의 얼굴 수정은 별도 후보로 기록·검토한 뒤 사용한다.
- 신규 이모티콘은 대표 문구의 서체·굵기를 비교해 한 세트의 기본 서체를 정한다. 글자가 원화보다 먼저 튀거나 음절별 크기 차이가 과하면 굵은 손글씨를 일괄 적용하지 않는다. v22는 Gaegu Regular·Bold와 비교해 **Gamja Flower Regular에 약한 획 보강**을 적용한 사례다. 활성 v18·최종 v24의 출력·폰트·OFL·출처 해시를 보존하고 덮어쓰지 않는다. 사용자 요청으로 종료한 v20~v23은 [이력 안내](../emoticons/kakao-32/history/README.md)에 따라 동일 바이트 보존 위치 또는 삭제 사실을 기록한다.
- 글자는 생성 이미지에 포함하지 않고 별도 레이어로 조립한다. **문구마다 실제 잉크 높이를 같게 확대하지 않는다.** 같은 서체·기준 문장(예: ‘장고야 부탁해’)으로 크기를 보정하고, 같은 등급의 모든 문구에 동일한 확대율과 글자 크기를 적용한다. 실제 문구의 잉크 높이·폭은 결과로 측정한다. 360px 기준 기준 문장의 잉크 높이를 일반 32px, 조용하거나 긴 문구 30px, 짧은 감탄 36px의 세 단계에서 시작한다. 이는 개별 문구의 높이를 강제하는 값이 아니다. 폭이 넘치면 문구·배치·세트의 크기 기준을 검토하고 가로로 찌그러뜨리거나 특정 문구만 몰래 축소하지 않는다.
- 흰 외곽선은 360px 기준 약 1.5–2px, 말줄임표는 본문 대비 약 55%에서 시작한다. 작은 출력에서 획이 약한 서체는 일정한 미세 획 보강을 비교할 수 있으며 서체 파일 자체를 수정하지 않는다. 기준 크기·획 보강·외곽선과 실제 잉크 측정을 제작 기록에 남긴다.
- 진한 차콜 글자와 흰 외곽선을 사용한다. 80px 어두운 배경에서는 외곽선이 가늘게 보일 수 있으므로 360px만 보고 확정하지 않는다. ‘미안해…’처럼 조용한 문구도 읽기 어려울 정도로 줄이지 않는다.
- 정확한 문구·읽기 순서를 유지하고 수평 배치를 기본으로 한다. 강조가 필요한 소수 컷은 ±3도 안팎에서 시작하며 도구의 지원 상한 ±10도를 기본 연출값으로 삼지 않는다. ‘헉!’은 짧고 크게, 조용한 표현은 절제해 표현한다. 모든 문구를 같은 모자 위 좌표에 배치하거나 모든 컷을 의무적으로 기울이지 않는다.
- 그림과 글자 사이 간격은 360px 기준 약 12–18px에서 시작해 실루엣에 맞춘다. 누운 자세·가로로 넓은 소품은 문구도 그림 가까이 이동해 한 덩어리로 읽히게 한다. 전신 비중을 먼저 확보하되 확대율을 모든 자세에 기계적으로 강제하지 않는다.
- 동작 주변 빈 공간과 누운 자세·카트·큰 소품의 전체 실루엣을 사용한다. 360px 기준 바깥 여백은 16px을 목표로 하며 최소 8px을 지킨다. 문구 없는 비교는 최종 스티커의 위치·크기에서 글자만 제거한 이미지다.
- 이모티콘은 투명 360×360 PNG, 개당 150KB 이하, 투명 가장자리, 문구와 그림의 충돌, 원화 잘림을 검사한다. 80px·120px의 밝고 어두운 배경에서 글자·표정·모자·장갑과 소품 연결·신발을 관찰한다. 작은 디테일이 약해지면 기록하고 핵심 감정·동작이 유지되는지 확인한다. SNS 컷은 정한 출력 크기와 실제 열람 크기에서 글자·표정·배치·합성 경계를 검토한다.

### 이모티콘 문구

생활 친구의 대사로 자연스럽고 실제로 보낼 상황이 분명한 짧은 한국어를 쓴다. 설명형 상태명보다 ‘내가 할게!’·‘다 됐어!’처럼 상대에게 건네는 말을 우선하며, ‘멍…’·‘절전 중…’처럼 자기 상태 자체가 반응인 컷은 짧게 살린다. ‘밥 먹었어?’·‘뭐 먹을까?’·‘잠깐만!’·‘난 패스!’처럼 잘 작동하는 문구는 유지한다. 문구·표정·동작이 같은 의도를 전달하는지 보고, 비슷한 뜻의 컷을 말만 바꿔 늘리지 않는다. 특정 유행어나 v21의 32개 문구를 모든 후속 세트에 강제하지 않는다. 앱 안내의 존댓말·기능 문구는 디자인 시스템을 따른다.

## 앱·브랜딩·영상

- 앱은 문구 없는 원화에서 균일 비율로 파생한다. 24번을 기본·아이콘·스플래시에 사용한다. 기존 Mascot mood·size API와의 호환성을 유지한다.
- 앱의 시각 표현·배치·장고 상호작용은 [디자인 시스템](../../../docs/design-system.md)을 따른다. 손그림 스타일은 캐릭터·배경 이미지에만 적용하고 카드·말풍선·버튼·제목·기능 아이콘·UI 글꼴에는 확장하지 않는다. 기존 화면의 장면·구도·정보 묶음·조작 위치를 유지하며 철회한 전체 개편·크레파스 UI 장식·v19 교체는 자동 재개하지 않는다.
- 크레파스 팔레트는 캐릭터 전용이다. UI 기능 색상에 직접 대입하지 않는다. UI 표현 변경은 공유 semantic token의 역할·대비를 검증해 반영하며 상태·기한 색의 의미와 Admin의 기존 기준은 유지한다.
- 앱 UI 글꼴은 Pretendard를 유지한다. 캐릭터·SNS·이모티콘 이미지의 레터링 규칙을 UI 글꼴에 적용하지 않는다. 필수 정보 뒤에는 질감을 넣지 않는다.
- 영상에서는 채택된 디자인의 구조·질감이 프레임 사이에서 일관적인지 확인한다. SNS의 의도한 변형과 이동·회전 중 우발적으로 생긴 부품·질감 깜박임을 구분한다.
- SNS 변형 허용은 앱의 비율 유지 파생, 기존 흰색 면·얇은 테두리·왼쪽 꼬리 말풍선, 이모티콘 제출 규격을 변경하지 않는다.
- 검수 중 불확실성은 그대로 기록한다. MASTER 지정·앱 파생 허용·사용자 SNS 채택·서명된 이모티콘 출시를 구분한다. 개별 변형 종류의 허용·검토 기준은 BIBLE에만 두며 중복 규칙을 만들지 않는다.
