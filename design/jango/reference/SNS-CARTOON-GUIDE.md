# 장고 SNS 카툰 릴스 제작 기준

2026-10-20부터 신규 연재의 기본 형식은 **처음부터 9:16으로 구성한 1080×1920px 카툰 릴스**다.
기본 연출은 가벼운 확대 또는 이동, 고정된 말풍선·대사, 사용 권한이 확인된 배경음악이다.
2026-10-24부터 기본 BGM은 **Monkeys Spinning Monkeys — Kevin MacLeod**이며 이후 신규 카툰 릴스에도 적용한다.
캐러셀은 사용자가 별도로 요청한 경우에 제작한다. 현재 규격과 변경 근거는
[채택 레지스트리](../cartoon-series.json)의 `currentProductionPolicy`에서 읽는다.

2026-10-09 채택된 `jango-sns-ep01-v6`는 장면 통합·이야기·한글 표현의 승인 참조로 유지한다.
승인 맥락과 대상 파일의 경로·SHA-256·Library ID·버전은 레지스트리의 기존 기록에서 읽는다.
[승인 전체 보기](../../../output/marketing/jango-sns-ep01-v19-review-v6/jango-ep01-v6-overview.png)와
[컷당 360px 보기](../../../output/marketing/jango-sns-ep01-v19-review-v6/review-mobile-360.png)를 함께 확인한다.
v6의 4:5 구도와 기존 2화의 4:5 이미지를 세로 여백 안에 넣은 변환 방식은 신규 릴스의 기본값이 아니다.
기존 이미지·영상·게시물·승인 기록은 보존하며, 이 규칙 수정으로 재제작하거나 재업로드하지 않는다.

## 정본의 역할과 우선순위

| 자료 | 역할 |
|---|---|
| [v18 원본 MASTER](../masters/v18/master.json)·[활성 참조](../style-master.json) | 장고의 공통 형태·선·색·크레파스 질감. 원본 바이트·해시를 유지한다. |
| [BIBLE](./JANGO-CHARACTER-BIBLE.md)·[STYLE GUIDE](./JANGO-STYLE-GUIDE.md) | 정체성·구조와 SNS 표현 확장의 허용·검토 기준. |
| [v18 원본 목록](../master-set.json) | 활성 원본 32종의 구조·입·표정·포즈와 그림체 계보. 단순 스티커 콜라주를 기본 제작 방식으로 되살리지 않는다. |
| 승인 v6 | 장면 통합·연출·대사·정보량·기능 전달의 품질 참조. 4:5 구도를 신규 릴스에 강제하거나 v18 MASTER를 대체하지 않는다. |
| 이 문서·현재 제작 정책 | 신규 카툰 릴스의 9:16 구성·시간·움직임·레터링·음악·커버·검수·게시 기준. |
| 회차별 콘티와 사용자 요청 | 주제·등장인물·공간·장면 수·시간·대사·동작·카메라·의도적 변형. 승인 범위 안에서 창의적으로 바꾼다. |

v1/v2의 기존 스티커·말풍선·배경을 단순 재배치하는 콜라주 방향은 철회된 참고 이력이다.
그 이미지나 당시 렌더러의 기본값을 신규 제작 기준으로 자동 선택하지 않는다. v3–v5도 제작 계보와
비교 자료이며 장면 품질의 승인 참조는 v6다. v4의 승인된 2컷과 v19 MASTER는 과거 채택·제작 계보로 보존한다. 2026-10-14 복원한 활성 v18 MASTER가 신규 장고 제작의 우선 기준이며 기존 승인 v6 이미지는 변경하지 않는다.
과거 파일을 삭제하거나 이름만 바꿔 승인본으로 표시하지 않는다. 현재 요청과 이 문서가 과거 카툰
프롬프트·README·스크립트 기본값보다 우선한다.

## 재현할 그림체·상대 크기·동작

- 신규 장고는 v18 원본의 크레파스 선·무광 색면·민트·차콜·살구 볼터치·약한 종이 결을 우선한다.
  사람·배경·소품과 선의 밀도·색·접촉 음영을 조화시키며 단순 스티커처럼 뜨는 합성은 보정한다.
  승인 v6의 장면 통합·연출 품질은 참고하되 과거 v19 연필 스타일을 장고의 공통 기본값으로 강제하지 않는다.
- v6의 여성·머리 모양·주방·두부·구도는 모든 회차의 필수 요소가 아니다. 같은 인물·공간이 이어지는
  회차에서는 얼굴·의상·소품·빛의 연속성을 유지한다. 새 인물·공간도 같은 재료감과 선의 밀도로 그린다.
- 장고는 사람과 상호작용하는 작은 동반자로 읽혀야 한다. v6 2컷은 함께 선 장면의 상대 크기,
  3컷은 가까운 카메라의 상호작용, 4컷은 식탁에서의 관계 참고다. 머리만 늘이지 말고 카메라 거리,
  바닥/식탁의 접촉면·가림으로 크기 변화를 설명한다. 측정하지 않은 비율을 고정 임계값으로 만들지 않는다.
- 승인 보존 때문에 v6 1·2컷에 남은 상대 크기 차이는 새 회차의 크기 점프를 정당화하는 기준이 아니다.
  같은 거리·장면에서의 연속성을 새로 검토한다. 의도적인 비율 과장은 BIBLE에 따라 기록·검토한다.
- 3컷의 장갑 전체 가리키기, 4컷의 기존 엄지 반응처럼 행동에 맞는 다른 자세를 쓴다. 두 팔·장갑·손목·소품의
  연결과 가림을 확인한다. 표정·입·반전·의상의 창의적 확장은 BIBLE의 절차를 적용한다.
- 전체 모습이 필요하면 모자·손·소품을 보존한다. 가까운 장면의 크롭은 명세에 의도를 적는다.
  v6 3컷의 오른쪽 모자 가장자리 접촉은 가까운 프레이밍 사례이며 모든 출력의 잘림 허용이 아니다.

## 세로 화면·안전 영역·움직임

- 콘티와 작화 프롬프트부터 9:16 세로 장면을 설계한다. 최종 프레임은 1080×1920px이며 배경과 장면이
  화면 전체를 채운다. 작은 4:5 카드 바깥에 단색 여백을 두는 구성을 기본으로 사용하지 않는다.
- 생성 원본의 실제 크기·비율을 기록하고 원본 바이트를 보존한다. 도구 출력 비율이 다르면 공식 imagegen으로
  배경을 확장하거나 장면을 재구성한 별도 후보를 만든다. 인물·글자를 비균일 확대하거나 핵심 요소를 잘라 맞추지 않는다.
- 좌상단을 원점으로 **x=96–900, y=280–1420**을 핵심 정보의 초기 배치 영역으로 둔다. 대사·얼굴·필수 앱 정보·
  행동 안내를 이 안에 배치하고 배경은 프레임 끝까지 이어 간다. 이 좌표는 프로젝트 기준이며 플랫폼의 고정 규격이나
  모든 기기에서의 가림 방지 보장이 아니다. 실제 Instagram 버튼·계정명·캡션이 겹친 상태에서 확인하고 필요하면 안쪽으로 보정한다.
- [Meta 릴스 제작 안내](https://www.facebook.com/business/ads/facebook-instagram-reels-ads)의 세로 영상·음향·안전 영역 원칙을
  참고한다(확인일: 2026-10-20). 해당 자료는 광고 안내이며 유기적 게시물의 성과 보장이나 위 좌표의 출처로 사용하지 않는다.
- 장면당 완만한 확대 또는 이동 한 종류를 사용한다. 확대는 화면을 채우는 기본 배율의 **100–104%** 안에서,
  이동은 배경의 빈 가장자리가 드러나지 않는 범위에서 시작·끝 위치를 콘티에 지정한다. 핵심 요소는 움직임의 전 구간에서 안전 영역 안에 둔다.
- 움직이는 작화와 고정된 말풍선·텍스트를 분리한다. 말풍선 꼬리가 화자와 어긋나거나 손·소품을 가리지 않게
  시작·중간·끝과 전체 재생을 확인한다. 장면 전환은 단순 컷 전환을 기본으로 하며 읽는 중인 문구를 흐리거나 겹치게 하지 않는다.

## 이야기·정보량·앱 효용

v6의 `저녁 고민 → 잊은 재료 발견 → 추천 메뉴 확인·선택 → 식사 만족`은 인과관계가 읽히는 사례다.
모든 회차를 같은 줄거리나 네 구도로 고정하지 않는다. 기본은 **4장면·24초(장면당 6초)**이며 주제와 읽는 시간에
맞춘 장면 수·순서·시간·시점·유머·감정·공간은 콘티에서 확정한다. 시청자가 상황, 장고/앱이 도운 행동,
달라진 결과를 이해해야 하며 무음으로 보아도 핵심 이야기가 전달되어야 한다.

- 첫 2초 안에 공감 상황이나 질문을 보여준다. 별도 로고 화면 때문에 이야기 시작이 늦어지지 않게 한다.
  마지막에는 브랜드와 효용 중심 행동 안내 하나를 최소 3초간 읽히게 둔다.
- 한 컷에는 핵심 행동 또는 발견 하나를 둔다. 대사·얼굴·조리·휴대전화·재료 더미를 동시에 같은 강도로
  강조하지 않는다. 배경은 분위기를 유지하되 핵심 행동보다 낮은 대비로 둔다.
- 대사 → 표정/시선 → 손·소품·선택 지점으로 읽히게 구성한다. 넓은 상황 컷, 재료나 화면의 가까운 컷,
  결과 컷을 섞고 같은 얼굴·포즈만 반복하지 않는다.
- 추천이 주제라면 이미 요리 중인 장면에 설명을 얹어 선택 과정을 대신하지 않는다. 등록 재료로 메뉴를
  확인하고 고르는 행동을 보여준다. 다른 효용을 다루는 모든 회차에 휴대전화를 강제하지는 않는다.
- 종료 컷은 브랜드명과 효용 중심 행동 안내 하나를 읽히게 둔다. v6의 `장고야 부탁해 / 내 재료로 오늘 메뉴 찾기`가
  사례다. 확인되지 않은 다운로드 주소·QR·프로필 이동 안내나 가짜 버튼은 만들지 않는다.
- 대사를 다 읽기 전에 장면이 넘어가면 문구를 줄이거나 재생 시간을 조정한다. 글자를 작게 하거나 빠르게 흘려 해결하지 않는다.

## 말풍선·한글·모바일 읽힘

- SNS 말풍선은 밝은 아이보리 면과 손으로 그린 갈색 연필 윤곽을 따른다. 글자 대비와 화자를 가리키는 꼬리를
  우선한다. [앱 디자인 시스템](../../../docs/design-system.md)의 흰색 면·얇은 테두리 말풍선은 별도 기준이다.
- 그림과 한글을 분리한다. 공식 imagegen으로 글자·말풍선이 없는 장면 원화를 제작하고, 필요한 빈 말풍선은
  별도 정지 레이어로 생성하거나 승인 에셋을 재사용한다. 말풍선·글자의 위치는 움직이는 원화에 종속시키지 않는다.
  대사·브랜드는 기존 Gaegu, 앱 화면 문구는 실제 앱과 같은 Pretendard로 별도 조립한다.
  생성 이미지의 유사 한글을 최종 문구로 채택하지 않는다. 폰트·라이선스 원본은 기존 경로를 참조한다.
- 승인 v6 원본은 컷당 1122×1402의 약 4:5 PNG로 보존한다. 신규 릴스는 별도 1080×1920px 장면으로 구성하고,
  원본과 **360×640px 영상**에서 대사·손동작·브랜드·행동 안내를 확인한다. 각 장면의 시작·중간·끝 정지 화면도 확인한다.
  2×2 전체 시트를 휴대전화 폭에 줄이거나 대표 프레임 하나만 보는 것으로 영상 검수를 대신하지 않는다.
- 1080px 출력의 조판 시작값은 **주요 대사 72px, 브랜드 80px, 행동 안내 54px**다. 360px 환산은 각각 약 24px,
  27px, 18px이며 실제 잉크 높이와 읽힘은 별도로 검토한다. 모든 문구의 강제 크기나 자동 통과 임계값이 아니다.
  긴 문장은 글자만 줄이지 말고 문구·줄 수·말풍선 여백을 조정한다.
- v6 휴대전화 보조 문구는 환산 약 10–15px로 작다. 새 회차의 필수 정보 기준으로 삼지 않는다.
  메뉴와 행동은 큰 대사·시선·접촉으로도 읽혀야 한다. 화면의 세부 정보가 핵심이면 화면을 더 크게 보여준다.
  오탈자·줄바꿈·넘침과 꼬리/손/얼굴의 충돌을 실제 픽셀에서 검토한다.

  구간 자르기·음량 조정·페이드 등 편집 내용과 필요한 크레딧·라이선스 링크·변경 고지를 캡션에 반영한다.
- 내레이션은 요청 시 추가하고 대사와 일치하는 자막을 검수한다. 음악만 있는 영상에 불필요한 자동 음성 자막을 넣지 않는다.
  음악의 시작·전환·끝을 자연스럽게 연결하고 전체 청취와 디코딩·음량·클리핑·연속성 검사를 구분해 기록한다.
  청취하지 못한 경우 청취 완료로 쓰지 않으며, 사용 권한이나 음향 문제가 해결되지 않으면 게시를 보류한다.
- 최종 출력은 **MP4 / H.264 / 1080×1920 / 30fps / AAC**다. 편집·인코딩 설정과 최종 파일 해시를 남긴다.
  브라우저 게시 화면에 음악 추가 기능이 없으면 사용 권한이 확인된 BGM을 영상 파일에 포함한다.
- **1080×1920px 커버를 별도로 준비**한다. 제목과 장고를 중앙에 배치하고 릴스 화면과 실제 프로필 썸네일의 잘림을 확인한다.
  프로필의 표시 비율을 영구 고정값으로 가정하지 않는다. 게시 도구에서 지정한 커버와 게시 후 보이는 커버를 대조한다.

## 실제 기능과 이야기 예시

제작 시점의 실제 앱 화면·코드와 [출시 범위](../../../docs/product/release-scope.md)를 확인하고
기능 근거 경로·확인일을 기록한다. v6는 등록 재료 기반 추천, 조건인 `임박 우선`, 요리 상세의
`사용할 재료`·기한 표시·`이 요리 시작`에 근거한다. 근거 파일은 레지스트리의 `featureEvidence`에서 읽고
후속 회차에서 최신 상태를 다시 확인한다.

실제 캡처, 실제 기능을 간략히 그린 화면, 이야기용 메뉴·날짜를 구분한다. 간략 화면을 현재 앱의 정확한
스크린샷으로 소개하지 않으며 생략·예시 여부를 제작 기록과 게시 문구에 밝힌다. 검증되지 않은 자동 인식,
기한 추정, 안전 보장, 자동 조리를 그림이나 대사로 암시하지 않는다. 선택 조건을 상시 동작으로 표현하지 않는다.

## 준비·생성·검수·채택

1. **콘티 확인:** 아래 양식으로 회차/후보 ID, 주제·효용, 장면별 행동·대사·연속성·재생 시간,
   카메라·움직임·안전 영역·고정 레터링·음악·커버·행동 안내를 정한다. 보존/변경 요소와 변형/크롭 의도를 적고,
   사용자가 콘티를 확인한 뒤 제작한다. 세션에 이미 있는 승인 발언과 범위를 기록하고 같은 허가를 중복 요청하지 않는다.
2. **참조:** 활성 v18 원본과 레지스트리의 승인 파일을 직접 열고 해시를 확인한다. 목표와 가까운 v6 컷은 장면/연출/통합
   품질 참조로 선택하고 수정 대상은 edit-target으로 구분한다. 장고의 형태·그림체는 v18, 장면·읽힘은 v6라고 역할을 명시한다.
   실제 첨부 순서의 imageIndex·경로·해시·역할을 기록하고 같은 파일은 한 번만 첨부한다. 최대 5개를 지키며
   전체 시트 속 작은 장고만 참조하는 대신 필요한 개별 승인 컷을 사용한다.
3. **생성 전 기록:** 실제 프롬프트·참조·목적·방법·변경 범위를 먼저 저장한다. 승인 v6를 다시 바꾸면 새 후보다.
   원본·과거 준비 기록을 덮어쓰지 않는다.
4. **작화·편집:** 새로운 장면·손·소품·가림·포즈·질감은 공식 imagegen으로 일관되게 생성/편집한다.
   기존 요소를 잘라 붙인 저품질 콜라주로 대신하지 않는다. 한글 조립·여백·규격 변환·전체 보기 등 검토된
   단순 처리는 기존 오프라인 도구를 재사용하며, 승인된 콘티에 따라 원화 움직임·고정 레터링·음악을 합성한다.
   유료 외부 API·생성형 동영상·내레이션·앱 이관·게시를 자동 추가하지 않는다.
5. **검수:** 원본과 360×640px 영상, 실제 Instagram 조작 영역, 프로필 썸네일에서 아래 검수표를 확인한다.
   전체 재생으로 읽는 시간·이동 중 잘림·전환·음향·검은 프레임을 확인하고 문제는 보정·재검토한다.
   반복 생성에도 별도 프롬프트와 실제 참조 기록을 남긴다. 자동 해시/문자 검사만으로 시각 통과를 선언하지 않는다.
6. **저장:** 생성 원본, 장면별 PNG·고정 말풍선/한글 레이어, 타임라인·편집 설정, 최종 MP4, 별도 커버,
   전체 보기·360×640px 검토 영상·UI 겹침/썸네일 캡처, 캡션·음악 사용 근거·제작·검수 기록을 회차 폴더에 저장한다.
   Library를 함께 사용하는 경우 편집본은 같은 항목에서 이전 버전을 보존하고 반환 ID·버전을 기록한다.
7. **채택:** 후보 → 비교 검토 → 보정 → 사용자 승인 → 승인 범위 내 재사용 순서를 지킨다.
   정확한 파일 해시와 승인 발언·맥락·용도를 별도 채택 기록에 묶는다. v6 승인을 새 회차에 자동 승계하지 않는다.
8. **게시:** 사용자에게 승인된 게시 범위에서 실행한다. 계정·영상 순서/길이·음악 포함 여부·별도 커버·캡션·
   음악 크레딧·기능/예시 고지·AI 콘텐츠 표시를 확인한다. AI 작화 사용은 캡션에 밝히고 제공되는 AI 표시 설정을 적용한다.
   릴스에 이미지별 대체 텍스트 입력란이 없으면 캡션에 간단한 장면 설명을 넣고 그 대체 방식을 기록한다.
   게시 후 실제 재생·음악·커버·캡션·프로필 다운로드 링크를 확인하고 주소·화면 캡처·남은 제한을 남긴다.

현재 `jango:prepare`는 이모티콘·스타일 참조용이며 SNS를 거짓 종류로 등록하지 않는다.
[매체별 절차](../quality/README.md)에 따라 별도 준비·검수 기록을 남긴다. 기존 v6 렌더러·프롬프트는
당시 재현 자료이지 새 회차의 현재 기준 선택기가 아니다. 과거 준비의 문서 해시가 현재와 달라져도
당시 스냅샷을 유지하며 재현 검사를 통과시키려고 과거 해시를 현재 값으로 덮어쓰지 않는다.
레지스트리의 기존 `guide.sha256`는 과거 기준 문서의 기록이며 현재 문서의 무결성 값으로 사용하지 않는다.
현행 가이드 해시는 `currentProductionPolicy.guide.sha256`에 기록한다. 이번 정책 변경은 새 작화의 채택이나 게시 허가가 아니다.
정책 개정 직전 문서는 `currentProductionPolicy.guideHistory`의 경로·해시로 별도 보관한다. 기존 이모티콘 정리 기록에
연결된 과거 문서 검사는 그 보관본을 원래 기대 해시와 대조하며, 과거 기대 해시나 승인 기록을 새 값으로 덮어쓰지 않는다.

새 회차 생성이나 게시 승인이 아니다.
