# 현재 모델 기준선 — 2026-10-20

운영 설정을 읽기 전용으로 확인한 뒤 고정 레시피 50조건과 온라인 사진 30장에 각각
1회 요청했다. 레시피 의미 보정 47회를 포함해 공급자 호출은 총 127회다. 요청은 순차
실행했으며 실패 조건을 교체하거나 다시 평가하지 않았다. 모델·프롬프트·판매 정책은
변경하지 않았다.

- 레시피: `gpt-5.4-mini`, prompt `recipe-recommendation-v12`, 출력 상한 3,500 tokens.
  35/50 성공(70%), 15건 모두 `semantic_validation` 실패. 비용 $0.855678,
  요청당 비용 중앙값 $0.017674·p95 $0.028063, 생성 시간 중앙값 15.839초·p95 25.142초.
- 사진: `gpt-5.6-luna`, 출력 상한 1,800 tokens. 영수증 15/15·냉장고 15/15 생성 성공.
  비용 $0.029125, 요청당 비용 중앙값 $0.000895·p95 $0.001778,
  생성 시간 중앙값 3.426초·p95 7.992초. 생성 성공은 인식 정확도를 뜻하지 않는다.
- 합계: 80요청·65성공, **$0.884803**. 80건 모두 공급자 usage가 보고됐다.
  실패·의미 보정 비용을 포함하며 $5 한도 이내다. Standard 가격표
  `openai-standard-2026-10-08`로 계산한 금액이며 청구서 최종 결제액과 구분한다.

성공 요청의 보정 포함 p95(레시피 $0.026895·사진 $0.001778)와
운영 환산 기준 1달러=1,500원을 적용한
`60 × 레시피 p95 + 30 × 사진 p95` 추정치는 **2,500.56원**이다.
858원을 초과하지만 성공 레시피가 35건이어서 기존 50건 성공 표본을 충족하지 못한다.
따라서 [보고서](report.json)의 원가 판정은 `incomplete`이며 합격으로 처리하지 않는다.
모델 교체 심사와 판매 예외 정책을 이 결과로 변경하지 않는다.

## 확인한 품질과 남은 검수

[출력 필드 감사](constraint-and-safety-field-audit.json)는 성공 레시피 35건·105개 요리의
인분·표시 시간·장비·재고 ID·수량·단위·구성 등 1,252개 필드를 독립적으로 비교했고
해당 필드 위반은 없었다. 비건 조건은 0/5, 달걀 알레르기 조건은 7/10 생성 성공이었다.
이 숫자는 출력 필드의 일관성과 생성 성공률이며 실제 조리 가능성·숨은 알레르겐 검증이
아니다. `synthetic-recipe-004`는 생쌀 재고를 미리 지은 밥으로 바꿔 가정하고 7분을
제시했다. `003`의 결착 재료 없는 채소전은 실제 조리 검증이 남아 있다.

사진 출력 145개 항목에서 명시한 유통기한은 없고 `needsReview=true`를 유지했다.
[부분 검토](manual-review-findings.json)에서는 외국어 영수증의 메뉴를 원재료로 바꾸거나
품목을 잘못 읽은 사례 최소 9개와 수량 오류 1개를 확인했다. 이는 사후 진단 사례의
하한이며 전체 정확도·재현율로 환산하지 않는다. 전체 누락·오인식·수량 검수, 독립
이중언어 검수와 조리·맛·안전 평가는 **미완료**다. 검수하지 않은 safety/quality 점수를
임의로 넣지 않았으므로 전체 기준선도 `complete=false`다.

10월 21일 [추가 오프라인 검토](offline-photo-review-2026-10-21.json)에서 영수증 15건의
음식·토핑 35행과 출력 35행을 대응시키고 냉장고 원본 15장을 확인했다. 행이 모두 대응해도
품목 인식이 정확하다는 뜻은 아니다. 맥주 라벨을 생강맥주로 바꾼 사례, 음료 병 누락·수량
부족, 달걀·마늘 품목 누락과 요구르트 수량 부족을 확인했다. 가려진 내용물·수량과
불확실한 품목은 채점하지 않았고 누락과 수량 오류를 중복 합산하지 않았다. 현행 프롬프트는
가정용품도 허용하므로 보이는 온도계는 오류로 집계하지 않는다. 독립 정답 주석과 사람의
조리 검증이 추가되지 않았으므로 전체 품질 평가는 계속 미완료다. 유료 재호출은 없었다.

## 입력과 재현 범위

[사진 출처·라이선스·해시](photo-provenance.json)는 사용자 요청에 따라 사용한 공개 자료
30장을 기록한다. 영수증은 NAVER CLOVA CORD v2(CC BY 4.0)의 음식·외식 영수증,
냉장고는 Wikimedia의 CC BY·CC BY-SA·public domain 사진이다. 한국 장보기 영수증이나
실제 한국 사용자 냉장고를 대표하지 않는 편의 표본이다. USDA 연출 사진과 단일 품목
사진도 포함한다. 입력 목록은 모델 호출 전에 고정했고 결과에 따른 제외는 하지 않았다.
영수증 프롬프트는 한국 마트·편의점을 대상으로 하므로 외국 외식 영수증 결과는 범위 밖
스트레스 사례다. 발견한 오류를 한국 장보기 영수증의 인식 정확도로 일반화하지 않는다.

냉장고 참조 이름은 부분 목록이다. `fridge-13`의 사전 라벨과 초기 검토 메모 모두 정확한
종류를 확정하지 못했다. [검토 이력](annotation-review-notes.json)에 초기 아보카도 단정의
철회와 미확정 처리를 남겼고 원본·입력 해시는 보존했다. 이 사례를 정답으로 단정해 모델의
오류를 계산하지 않는다. 단순 이름 일치 F1은 진단 값이며 인식 정확도가 아니다.
레시피는 기존 합성 자료의 앞 50건이다. 기존 자료의 절대 날짜와 상대 기한 간 불일치도
수정하지 않았으므로 실제 식품 안전성을 평가하는 표본으로 사용하지 않는다.

[레시피 조건](recipe-cases.jsonl), [사진 조건](photo-cases.jsonl),
[레시피 결과](recipe-results.jsonl), [사진 결과](photo-results.jsonl),
[파일 해시](evidence-sha256.json)를 보존한다. 원본 사진은 저장소에 복제하지 않았으며
원본 URL·다운로드 바이트 해시로 식별한다. 현재 로컬 원본은
`/tmp/jango-ai-baseline-data-20261020`에 있다. 원본 제공자가 파일을 바꾸거나 내리면 동일
바이트 재수집이 불가능할 수 있다.

검수 후 기존 결과를 `ai:evaluate:baseline:report --output-dir ... --grades ...`로 다시
보고할 수 있다. 이 명령은 공급자 호출을 하지 않는다. 유료 실행의 자동 재시도·재개는
수행하지 않는다.
