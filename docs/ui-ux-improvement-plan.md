# 주요 사용자 흐름 개선 실행 기록

## 2026-09-10 사진 등록·조리 완료·온보딩 개선

사용자 요청에 따라 다음 세 개선안을 우선순위 순서로 적용했다.

1. 사진 등록의 일괄 수정에서 보관 위치와 유통기한을 분리하고 각각 적용 대상 수를 표시한다.
   기본값은 미입력 항목만 채우기이며, 자동으로 채워진 보관 위치와 명시적으로 선택한 기한 모름은
   보존한다. 전체 적용은 대상 수를 확인한 뒤 덮어쓰기 버튼을 눌러야 반영한다.
   적용 직후 되돌리기를 제공하며, 이후 개별 수정이 발생하면 이전 되돌리기를 숨겨 새 입력을 보호한다.
2. 조리 완료 화면의 보관함 보기 버튼을 실제 보관함으로 연결했다. 재고 반영 결과와 되돌리기를
   장보기 제안보다 먼저 배치해 조리 후 남은 양을 우선 확인할 수 있게 했다.
3. 온보딩을 한 화면으로 줄이고 로그인하고 시작하기를 주 행동으로 제공한다. 기존 신호등 컴포넌트로
   사용 예시를 보여 주되 실제 보관함이 아님을 명시한다. 사용법은 선택형 안내 시트로 제공한다.
   로그인 요구와 온보딩 완료 처리, API·공유 계약은 유지한다.

검증 결과: 전체 테스트 1,015개(shared 121, mobile 457, API 437), 린트, 전체 타입 검사와
Android·iOS Expo JavaScript 번들 내보내기가 통과했다. 신규 테스트는 미입력 값 보존,
덮어쓰기 확인·취소, 되돌리기와 후속 편집 보호, 완료 화면 이동·정보 순서, 온보딩 시작·선택형 안내를 검증한다.
로그는 `apps/mobile/e2e/results/ux-priorities-2026-09-10/primary-flow-test.log`와
같은 폴더의 `primary-flows-android.log`, `primary-flows-ios.log`에 남겼다(gitignored).
작은 화면·큰 글자·태블릿의 네이티브 전후 캡처는 기존 실행 환경 제약으로 미완료이며,
번들 성공을 화면 검증으로 간주하거나 기준 이미지·비교 허용치를 변경하지 않았다.

## 2026-09-10 홈·보관함·등록 방식 개선

### 최종 홈 구성 — 사용자 요청에 따른 기존 신호등 복원

후속 요청으로 2×2 ‘오늘 확인할 재료’ 요약과 별도 재료 확인 버튼을 제거했다.
현재 홈은 **장고 히어로 → 기존 유통기한 현황 → 재료 넣기 → 요리 추천 → 브리핑** 순서다.
진행 중인 조리의 재고 반영 카드가 있으면 재료 넣기와 요리 추천 사이에 유지한다.
유통기한 현황은 기존의 가로형 **확인·만료·곧·여유** 순서, 신호등 아이콘·색·빛 효과,
모바일/태블릿 크기와 0건 표시, 보관함 필터 이동을 그대로 복원했다.
히어로의 기한 경과·미입력 안내, 로딩·오류 처리, 보관함 ‘사용 기록’·풀어 쓴 기한,
등록 방식 고정·사진 초안 이어서는 유지한다. 아래 2×2 구성과 관련 수치는 이전 단계 기록이며
현재 홈 디자인의 기준은 이 단락이다. 삭제한 요약 컴포넌트 전용 테스트를 정리하고,
기존 신호등 계약 및 히어로→기한 현황→등록→추천→브리핑 순서 검사를 적용했다.
네이티브 전후 캡처는 기존에 명시한 실행 환경 제약으로 여전히 미완료다.
복원 후 문서·린트·전체 타입 검사 및 전체 테스트 1,005개(shared 121, mobile 447,
API 437)가 통과했다. 로그는 `apps/mobile/e2e/results/ux-priorities-2026-09-10/restored-traffic-test.log`다.

사용자가 요청한 세 개선안을 구현했다. 시작 시 작업 트리는 깨끗했다.

| 대상 | 변경 전 → 변경 후 | 확인 근거 |
|---|---|---|
| 홈 | 등록·브리핑·추천 뒤의 기한 현황 → 최상단 ‘오늘 확인할 재료’, 기한 지남/7일 이내/기한 미입력/8일 이상을 구분 | `home.tsx`, `home-inventory-summary.tsx` |
| 홈 행동 | 항상 강조된 재료 등록 → 빈 보관함은 첫 등록, 재고가 있으면 기한 지남→7일 이내→미입력 순서의 확인 버튼. 각 상태와 버튼은 해당 보관함 필터로 연결 | `home-notices.ts`, `home-notices.test.ts`, `inventory-ux.test.tsx` |
| 보관함 | 아이콘만 있는 사용량 반영, D-day 표기 → ‘사용 기록’, ‘3일 남음/3일 지남/오늘까지/기한 미입력’. 재료명·기한을 먼저 읽고 위치·수량·날짜를 보조로 표시 | `InventoryCard.tsx`, `inventory-ux.test.tsx` |
| 등록 시트 | 최근 방식·초안에 따른 재정렬 → 바코드/사진/직접 입력 고정, 최근 사용은 배지만 표시. 사진 초안은 별도 이어서 버튼 제공 | `ingredient-entry-method-sheet.tsx`, `inventory-ux.test.tsx` |

장고 안내는 홈 요약 안에 배치하며 최초 오류는 재시도 안내를 유지한다. 조회 중에는 0건이나
빈 보관함으로 단정하지 않는다. 브리핑은 요리 추천 아래로 옮겼다. 기한 미입력 재료가 있으면
‘급한 재료 없음’ 대신 기한 확인을 안내한다. 재료명과 메타데이터는 줄 수 제한을 제거했고,
기한 배지는 고정 원형 대신 내용에 맞게 늘어난다. 기존 소비·폐기·되돌리기와 사진 초안 저장,
공간별 최근 방식, 등록 후 복귀, 사진 기능 플래그는 유지한다. 사진 초안이 있을 때 사진 방식에
진입하면 기존 초안을 먼저 확인하며, 이를 시트 설명에도 명시했다.

### 이번 변경의 검증과 남은 관문

사용자 후속 요청으로 ‘오늘 확인할 재료’의 **2×2 배치를 유지하면서 기존 신호등 램프를 복원**했다.
각 칸은 공통 `StatCard`의 `traffic` 변형을 사용한다. 순서는 기한 지남(코랄·느낌표),
7일 이내(노랑·시계), 기한 미입력(기존 미입력색·가로선), 8일 이상(라임·체크)이다.
모바일에는 compact 램프, regular-width/태블릿에는 기본 램프를 사용하고 큰 글자의 이름·건수는
기존 컴포넌트의 세로 배치를 따른다. 건수가 양수일 때만 켜지며, 빛 효과는 기한 지남·7일 이내에만
허용한다. 터치 영역의 접근성 이름은 유지하고 내부 램프의 중복 낭독을 막았다.
이 시각 변경은 사용자 요청에 따른 것이며 API·공유 타입·필터 이동·주 행동·로딩·빈 상태는 유지한다.
램프 매핑·0건/양수·모바일/태블릿·큰 글자 관련 UI 사례 6개를 추가했다.
램프 반영 후 문서·린트·모바일 타입 검사와 전체 테스트 1,017개(shared 121, mobile 459,
API 437)가 통과했다. 전체 테스트 로그는 같은 결과 디렉터리의 `lamp-test.log`에 남겼다.
전후 화면 비교는 사용자와 합의한 대로 네이티브 실행 환경 준비 후 수행한다.

- 새 기능 UI 테스트 19개: 상태별 주 행동·네 필터 연결, 확정 빈 상태/조회 중 구분,
  최근 방식 4종·초안 유무·사진 기능 비활성, 날짜 경계·사용 기록과 수정 분리·선택 모드 검증.
- 홈 안내 테스트 3개 추가: 기한 경과 우선, 임박 목록 미리보기가 없어도 집계 기준 안내,
  기한 미입력 안내. 기존 홈 순서·신호색 계약은 의도된 새 화면 구조에 맞춰 갱신했다.
- 모바일 TypeScript, `pnpm docs:check`, `pnpm lint` 통과.
- `pnpm typecheck`: 최초 shared esbuild가 샌드박스 상위 경로 접근 제한으로 실패했다.
  동일 명령을 제한 밖에서 실행해 shared build 및 모든 앱 타입 검사 통과.
- `pnpm test`: 160개 파일, 1,011개 테스트 통과(shared 121, mobile 453, API 437).
  첫 실행에서 이전 홈 순서를 고정한 계약 테스트 1개가 실패해, 요청된 새 우선순위를 검사하도록
  갱신 후 전체 재실행했다. Admin은 독립 test script가 없다. 로그 위치:
  `apps/mobile/e2e/results/ux-priorities-2026-09-10/test.log` (gitignored).
- `e2e:layout`, `e2e:layout:ios`: Bash 실행 단계에서 `The system cannot execute the specified program`.
  adb·emulator·Maestro 및 기본 Android SDK 경로가 없으며 네이티브 테스트는 시작되지 않았다.
- `screenshots:compare`: `current/small-three-button` 캡처 디렉터리 부재로 실패.
  **전후 스크린샷과 실기기 레이아웃 검증은 미완료**다. 기준 이미지·비교 허용치·승인 라벨은 변경하지 않았다.
- 레이아웃 smoke에 남아 있던 이전 재료 수정 버튼 문구를 현재 재료 행의 접근성 이름과
  ‘전체 내용 수정하기’ 시트 동작으로 갱신했다. 코드 대조로 확인한 오래된 선택자 수정이며
  네이티브 실행 성공을 의미하지 않는다.
- 후속 환경 재확인: 설치된 `C:/Program Files/Git/bin/bash.exe`로 Android 레이아웃 스크립트를
  실행하면 `adb is required for layout E2E.`에서 종료된다. 기본 Bash 연결 문제를 우회해도
  Android SDK·기기 실행 환경이 없어 캡처 관문은 여전히 막혀 있다.
- Android·iOS Expo export는 모두 통과했다. `EXPO_NO_DOTENV=1`로 로컬 env 파일 로딩을
  끄고 각각 `dist/ux-priorities-android`, `dist/ux-priorities-ios`에 Hermes 번들을 생성했다.
  로그는 위 결과 디렉터리의 `export-android.log`, `export-ios.log`에 있다. 번들 생성 검증이며
  APK/IPA 설치, 네이티브 화면 렌더링 또는 스크린샷 비교를 대신하지 않는다.
- 후속 기기 검증: 작은 화면/큰 글자/태블릿에서 홈 주 버튼 도달성, 네 상태 문구 줄바꿈,
  보관함 긴 재료명·기한 배지·사용 기록 버튼, 초안 있음/없음의 등록 시트를 전후 비교한다.
  사용 기록은 전부/일부 선택과 되돌리기까지, 등록은 세 방식의 기존 화면 복귀까지 확인한다.
  실제 사용성 세션과 5초 이해도 평가는 미실행이며 과업 시간·오조작률 개선 수치를 주장하지 않는다.

이 문서는 첫 UI/UX 개선 단계의 범위와 검증 기록이다. 제품 정책은
[출시 범위](./product/release-scope.md), [수익화](./monetization.md),
[디자인 시스템](./design-system.md), [반응형 QA](./mobile-responsive-qa.md),
[캐릭터 규칙](./JANGO_CHARACTER_STYLE_GUIDE.md)을 따른다. 기존
[홈 빠른 동작 초안](./product/home-quick-actions-ux-improvements.md)은 가설 자료이며,
이미 구현된 등록 방식 선택·빠른 저장·사진 초안 복원을 다시 만들지 않는다.

## 기준 상태와 검토 범위

- 시작 시 `git status --short`와 diff가 비어 있었다. 적용 규칙은 루트 `AGENTS.md`다.
- 변경 전 `pnpm --filter @expirymate/mobile test`: 81개 파일, 387개 테스트 통과.
- 변경 전 `pnpm docs:check`: 통과. 위 기준 검사에서 기존 실패 없음.
- 코드·테스트·활성 정본을 검토했다. 실제 사용자 관찰이나 실기기 검증 결과는 아니다.
- Windows 로컬에 adb, Android emulator, Maestro, Docker가 없고 기본 Android SDK 경로도
  존재하지 않는다. iOS simulator 실행 환경도 없다. 네이티브 전후 캡처는 미확보다.
- 운영 서비스, 스토어, production DB에 접근하지 않는다. 날짜가 있는 운영 기록은 현재 상태로
  재해석하지 않는다.

## 단계와 완료 조건

### 1. 등록 후 원래 작업 복귀

- 대상: 등록 경로 helper, 추천 진입, 수동·스캐너·사진 완료/취소/방식 전환.
- 변경: 추천에서 등록한 경우 추천 화면으로 돌아간다. 사진 완료 버튼은 실제 목적지를 말한다.
- 보존: 기존 `from=home/inventory`, 누락·잘못된 `from`의 홈 기본값, 연속 추가, 저장 API와
  중복 제출 제어, 세션/공간별 초안, 명시적으로 선택하는 기존 추천 생성 동작.
- 새 복귀 맥락은 URL의 추가 파라미터로 전달한다. 서버 상태나 사용자 선택을 새 전역 store에
  복제하지 않는다. 추천 화면이 스택에 있으면 기존 인스턴스로 돌아가 로컬 옵션을 유지한다.
- 완료 조건: 세 방식 모두 복귀 맥락 전달, 완료·취소·수동 전환 검증, 기존 링크 회귀 없음,
  단순 복귀가 새 `autoGenerateAt`을 만들지 않음. 네이티브 상호작용과 캡처는 별도 관문이다.
- 되돌리기: 이 단계의 등록 helper·소비 화면·테스트 변경만 역패치한다. DB/로컬 저장 migration 없음.
- 상태: 구현 완료. 등록·스캐너·추천 관련 59개 테스트 및 모바일 TypeScript 검사 통과.
  스캐너 저장 항목 수정 경유도 복귀 맥락을 유지한다. 새 `returnTo=recommendations`를 사용하고
  기존 `from=recommendations`는 그대로 홈으로 해석한다. 네이티브 스택·선택 유지 확인은 미실행.

### 2. 구독 상태와 다음 행동을 정확히 안내

- 대상: 구독 화면의 조회 상태 표시와 신규 판매 안내.
- 변경: 상태 확인 중, 최초 조회 실패, 마지막 확인 상태와 갱신 실패를 구별한다.
  구독·판매 가능 상태를 확인할 수 없으면 구매 UI 대신 조회 상태와 안전한 재시도를 제공한다.
- 보존: 가격·월간 기본 선택·무료 기능·법적 고지·스토어 상품·결제/복원 처리·서버 권한·feature flag.
- 완료 조건: 데이터 없음이 무료/판매 중단으로 단정되지 않음, 오류 후 재시도,
  확인된 상태에 따른 판매 UI, 기존 활성 혜택·복원 동작 회귀 없음.
- 되돌리기: 구독 표시 관련 helper·화면·조회 상태 노출·테스트 변경만 역패치한다.
- 상태: 구현 완료. 구독 표시·수익화·디자인 계약 66개 테스트 및 모바일 TypeScript 검사 통과.
  조회 상태 판단 18개, 기능 UI의 표시·재시도 연결 9개 테스트를 추가했다.
  기능 UI 테스트는 공통 네이티브 컴포넌트를 대체한 반환 트리 검사이며 실제 layout 검사가 아니다.

## 검증과 미완료 관문

단계별 관련 테스트 → 전체 docs/lint/typecheck/test → 관련 build와 CI 검사를 실행한다.
전체 검사 결과는 아래에 갱신한다. 정책·API·DB·저장 키·브랜딩 에셋은 변경하지 않는다.

### 네이티브 재검증 준비

- `.maestro/registration-return.yaml`을 추가했다. 격리된 로컬/테스트 API에 로그인하고
  쓰기 가능한 공간을 선택한 네이티브 앱에서 실행한다. 재료 1건을 저장하므로 운영 환경에서는
  실행하지 않는다. 사진 초안이 없는 테스트 계정을 사용한다.
- `apps/mobile`에서 `SCREENSHOT_DIR`를 별도 증거 디렉터리로 지정한 뒤
  `maestro test .maestro/registration-return.yaml`을 실행한다. 4인·60분 선택 → 수동 등록 →
  추천 복귀와 선택 유지, 스캐너·사진 닫기 복귀를 확인한다. 새 흐름은 아직 실행하지 않았다.
- 기존 layout smoke의 등록 방식 3곳이 현재와 다른 과거 버튼 문구를 사용하고 있었다.
  해당 선택자를 기존 `ingredient-entry-*-button` test ID로 교체했다. 실행 시 관찰한 실패가 아닌
  코드 대조로 확인한 기존 검증 문제다. 캡처 목록·baseline·비교 허용치는 변경하지 않았다.
- 바코드 실제 인식·빠른 저장·항목 수정 경유, 사진 분석·저장·초안 복원,
  조회 실패·재시도 시 구독 화면은 네이티브 환경의 수동/통합 QA에도 포함한다.
- 새 흐름의 선택 유지 assertion은 Maestro의
  [선택 상태 selector](https://docs.maestro.dev/reference/selectors/state-selectors)를 사용한다.
  두 YAML은 구문·문서 구조 검사만 통과했으며 Maestro 실행 통과를 의미하지 않는다.
