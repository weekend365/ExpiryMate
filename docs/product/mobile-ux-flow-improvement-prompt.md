# 장고야 부탁해 · 주요 유저 플로우 2차 UI/UX 개선 지시 프롬프트

아래 프롬프트는 현재 모바일 앱을 코드 기준으로 다시 검토한 뒤, 다른 구현 에이전트에게
그대로 전달할 수 있도록 작성한 실행 지시서다. 2026-07의 1차 리디자인을 되풀이하지 않고
정보 구조, 의사결정 수, 상태 전환, 오류 복구, 접근성, 수익화 맥락을 다듬는 데 집중한다.

## 현재 코드에서 확인한 핵심 진단

| 우선순위 | 관찰 | 개선 방향 |
| --- | --- | --- |
| P0 | 홈에 장고 히어로, 재료 등록, 브리핑, 추천, 재구매, 유통기한 현황이 연속 노출되어 오늘 해야 할 행동과 탐색 콘텐츠가 경쟁한다. | 최상단에는 현재 가장 중요한 행동 하나만 남기고 나머지는 요약·점진 공개한다. |

## 복사해서 사용할 마스터 프롬프트

```text
너는 “장고야 부탁해(Jango)” 모바일 앱의 수석 Product Designer이자 React Native/Expo
프론트엔드 엔지니어다. 현재 구현된 주요 사용자 여정을 코드와 실제 렌더 결과를 기준으로
검토하고, 비즈니스 로직을 보존한 채 UI/UX와 디자인을 2차 개선하라.

이번 작업은 1차 스타일 리디자인의 반복이 아니다. 기능을 더 보태기보다 사용자가 매 순간
해야 할 결정을 줄이고, 핵심 행동을 더 빨리 찾고, 중단 후에도 안전하게 이어갈 수 있게 만드는
것이 목적이다.

### 0. 작업 전에 반드시 읽을 기준

- AGENTS.md
- docs/JANGO_CHARACTER_STYLE_GUIDE.md
- docs/product/release-scope.md
- docs/monetization.md
- docs/mobile-responsive-qa.md
- packages/shared/src/design/tokens.ts
- apps/mobile/src/shared/theme.ts
- apps/mobile/src/components/*

`docs/archive/MOBILE_REDESIGN_PROMPTS.md`는 과거 완료 기록이므로 새 구현의 정본으로 사용하지
말고, 이미 수행한 작업을 파악하는 참고 자료로만 읽어라.

### 1. 절대 지켜야 할 제품·기술 경계

1. UI 구조, 시각 위계, 카피, 인터랙션 표현만 개선한다. API schema, endpoint, query key,
   mutation payload, 캐시 정책, 상태 저장 형식, 인증·초대 복귀 경로를 바꾸지 않는다.
2. 구독 가격·혜택·한도·자동 갱신·판매 플래그, 보상형 광고 정책, 쿠팡 파트너스 고지와
   개인정보·법적 문구의 의미를 바꾸지 않는다.
3. 기존 analytics/monetization event와 testID를 삭제하거나 이름을 바꾸지 않는다. UI 이동으로
   새 측정이 꼭 필요하면 기존 이벤트와 중복되지 않는 최소 이벤트만 제안하고 구현 전 보고한다.
4. `@expirymate/shared` 디자인 토큰, `AppText`, `AppTextInput`, `Button`, `Screen`,
   `BottomSheet`, `StepFlow`, `FeedbackBanner`, `EmptyState`, `Mascot`를 우선 재사용한다.
5. raw hex, 임의 타이포 수치, off-grid spacing, 48px 미만 터치 타깃을 만들지 않는다.
6. 장고 PNG를 화면에서 직접 import하지 않는다. `Mascot`와 승인된 mood만 사용한다.
7. 신규 마스코트·배경·아이콘 에셋을 생성하거나 기존 원본을 수정하지 않는다.
8. 현재의 5개 탭(홈·추천·보관함·장보기·설정)은 제품 결정 없이 삭제·추가·순서 변경하지
   않는다. 탭 내부 정보 구조는 개선할 수 있다.
9. 한 번에 전체 앱을 대규모 재작성하지 않는다. 아래 단계별로 작게 구현하고 각 단계마다
   typecheck, 관련 테스트, 렌더 캡처를 통과한 뒤 다음 단계로 간다.
10. 로딩·빈 상태·부분 실패·오프라인/재시도·권한 거절·중복 제출·긴 텍스트·키보드·뒤로가기까지
    정상 상태와 같은 수준으로 설계한다.

### 2. 먼저 할 일: 구현 전 UX 감사

코드를 바로 수정하지 말고 다음 산출물을 먼저 짧게 작성하라.

- 아래 8개 핵심 플로우별 현재 경로와 분기 상태를 표로 정리한다.
- 각 플로우에서 사용자가 내려야 하는 결정 수, 주요 이탈 지점, 복구 수단을 기록한다.
- 화면별 주 CTA와 보조 CTA를 표시하고, 주 CTA가 2개 이상 경쟁하는 곳을 찾는다.
- 로딩/빈 상태/부분 오류/전체 오류/완료/재시작 상태가 빠진 화면을 찾는다.
- 작은 화면, 최대 글자 크기, 키보드 표시 상태에서 잘릴 가능성이 있는 고정 푸터·시트를 찾는다.
- 발견 사항을 P0/P1/P2로 나누고, 수정할 파일과 그대로 둘 로직을 명시한다.

감사 결과를 보여준 뒤 아래 지시대로 구현을 계속하되, 새 기능이나 정책 결정이 필요한 항목만
“제안”으로 남기고 임의 구현하지 마라.

### 3. 공통 디자인 방향

브랜드 키워드는 “따뜻한 주방, 믿을 수 있는 정리, 옆에서 챙겨주는 장고”다.

- 배경 일러스트는 장면의 분위기만 만든다. 텍스트·컨트롤 뒤에는 충분한 불투명 surface 또는
  명도 대비를 두고, 배경과 카드 테두리가 서로 경쟁하지 않게 한다.
- 화면의 깊이는 `background → surface → tonal state` 3단계 안에서 해결한다. 모든 섹션을
  테두리 카드로 감싸지 말고, 여백과 섹션 제목만으로 묶을 수 있으면 카드 사용을 줄인다.
- Primary 민트는 선택·진행·주 CTA에 집중한다. danger는 만료·폐기·삭제, warning은 임박·확인
  필요에만 사용한다. 단순 정보에 상태색을 남발하지 않는다.
- 한 화면의 대표 장고는 최대 1개다. 장고가 상태를 설명하면 같은 블록에 의미가 중복되는 큰
  아이콘을 함께 두지 않는다. 반복 성공 배너는 장고 없이도 된다.
- 장고 mood는 `think=처리 중`, `speak=안내`, `point=다음 행동`, `happy=완료`,
  `worry=위험/복구`, `empty=실제 빈 상태`로 일관되게 사용한다.
- 제목은 결과나 사용자 목표를 먼저 말하고, 설명은 다음 행동을 한 문장으로 안내한다.
  친근한 말투를 유지하되 모든 버튼을 긴 대화문으로 만들지는 않는다. 버튼은 짧고 예측 가능하게
  쓴다. 예: “재료 추가”, “추천 받기”, “요리 시작”, “다시 시도”, “완료”.
- 페이지 전환은 탐색, BottomSheet는 짧은 선택·확인, StepFlow는 순서가 있는 입력에 사용한다.
  긴 콘텐츠를 무조건 BottomSheet에 넣지 않는다.
- 모션은 상태 전환을 설명할 때만 160~240ms 수준으로 사용하고 Reduce Motion 설정을 존중한다.
- sticky footer는 거래·입력·요리처럼 다음 행동이 명확한 화면에만 사용한다. 읽기 화면에서는
  콘텐츠를 가리지 않는 인라인 행동을 우선한다.

### 4. 주요 플로우별 개선 지시

#### A. 첫 진입 → 온보딩 → 로그인/가입 → 홈

핵심 파일:
- apps/mobile/app/index.tsx
- apps/mobile/app/onboarding.tsx
- apps/mobile/app/auth/*.tsx
- apps/mobile/src/features/auth/*

요구사항:
- 온보딩은 가치 3개 이내로 압축한다: “기한을 챙김”, “남은 재료로 요리”, “함께 관리”.
  마지막 로그인 안내만을 위한 별도 슬라이드는 제거하거나 마지막 가치 화면의 CTA에 통합한다.
- 첫 화면에는 앱명, 장고, 한 문장 가치, CTA만 둔다. 장식 배경 위 텍스트 대비를 검증한다.
- 소셜 로그인을 1차 경로로 유지하고 이메일은 접힌 보조 경로로 유지한다. 사용자가 이메일 입력을
  펼친 뒤 오류가 나도 입력값과 펼침 상태를 보존한다.
- 가입·메일 인증·비밀번호 재설정·초대 복귀에서 “현재 단계 / 다음에 일어날 일 / 다른 선택”이
  한눈에 보이게 한다.
- 세션 분기와 `returnTo`, 미완료 가입, 이메일 인증 대기, 공유 초대 복귀 로직은 변경하지 않는다.

완료 기준:
- 신규 사용자가 첫 재료 등록 진입까지 길을 잃지 않는다.
- 뒤로가기와 앱 재실행 후에도 인증·초대 맥락이 보존된다.
- 오류는 입력을 지우지 않고 필드 가까이에서 복구할 수 있다.

#### B. 홈 → 오늘 할 일 → 재료 등록/임박 처리/추천

핵심 파일:
- apps/mobile/app/(tabs)/home.tsx
- apps/mobile/src/features/home/*
- apps/mobile/src/components/JangoHeroNoticeCarousel.tsx
- apps/mobile/src/components/SpaceSwitcher.tsx

요구사항:
- 홈 최상단에는 우선순위가 가장 높은 상태 하나만 노출한다. 우선순위는 전체 로딩/오류 → 하던
  요리·미반영 재고 → 만료 → 임박 → 추천 완료 → 빈 냉장고 → 평온 상태 순으로 검토한다.
- 중요한 상태를 캐러셀 안에 숨기지 않는다. 캐러셀을 유지한다면 대표 상태는 고정하고 보조 알림만
  넘길 수 있게 한다.
- 첫 화면에서 “현재 냉장고”, “오늘 먼저 할 일”, “재료 추가”를 스크롤 없이 찾을 수 있게 한다.
- 장고 브리핑, 추천 미리보기, 재구매 제안, 유통기한 현황은 동일한 시각 무게를 갖지 않게 한다.
  오늘 할 일 다음에 추천, 현황, 선택적 상업 콘텐츠 순으로 위계를 낮춘다.
- 유통기한 4개 지표는 색만으로 구분하지 않고 라벨·수량을 함께 유지한다.
- 홈에서 보관함 필터로 이동할 때 선택한 상태가 유지되고, 돌아오면 홈 스크롤·공간 맥락이
  불필요하게 초기화되지 않게 한다.

완료 기준:
- 사용자가 3초 안에 “오늘 무엇을 해야 하는지”와 “재료를 어디서 추가하는지” 찾을 수 있다.
- 제휴/구독 콘텐츠가 임박·만료 행동보다 위에 오지 않는다.

#### C. 재료 추가 방식 선택 → 수동/바코드/사진 → 등록 완료

핵심 파일:
- apps/mobile/src/features/registration/ingredient-entry-method-sheet.tsx
- apps/mobile/app/register.tsx
- apps/mobile/app/scanner.tsx
- apps/mobile/src/features/scanner/*
- apps/mobile/app/register-photo.tsx
- apps/mobile/src/features/photo-intake/*

요구사항:
- 방식 선택 시 “추천 방식”은 최근 사용·남은 초안·등록 개수 맥락으로 하나만 강조한다. 바코드,
  사진, 직접 입력 각각에 적합한 상황을 짧게 설명한다.
- 수동 등록은 현재 단계 흐름과 빠른 기본값을 유지하되, 사용자가 어느 단계에서든 이전 값으로
  돌아갈 수 있게 한다. 마지막 단계에 이름·수량·위치·기한 요약을 보여준다.
- 수동 등록 완료 화면의 행동 위계를 `같은 방식으로 계속`(primary), `완료`(secondary),
  `다른 방식 사용`(tertiary/text) 순으로 정리한다.
- 스캐너는 카메라 안에서 스캔 영역, 짧은 안내, 닫기, 손전등/직접 입력처럼 꼭 필요한 조작만
  보인다. 인식 결과 편집은 시트에서 처리하고 권한 거절 시 OS 설정과 직접 입력 경로를 제공한다.
- 사진 등록은 “사진 선택 → AI 분석 → 검토 → 저장”의 현재 위치를 항상 보인다. 처리 중 앱을
  떠나도 괜찮은지, 초안이 보존되는지를 명확히 말한다.
- 사진 검토에서는 `확인 필요/중복 의심` 항목을 상단에 먼저 모으고 하나씩 해결한다. 정상 항목은
  접힌 요약 목록으로 둔다. 카드마다 모든 편집 컨트롤을 동시에 펼치지 않는다.
- 일괄 위치·기한은 상단 또는 별도 시트의 명시적 도구로 제공하고, 적용 후 되돌리기 또는 변경
  결과를 확인할 수 있게 한다.
- 저장 가능 개수와 남은 확인 개수를 sticky footer 가까이 표시한다. 일부만 저장 가능한 정책은
  기존 로직을 확인해 표현하고 임의로 바꾸지 않는다.
- 중복 재료의 “수량 합치기 / 별도 추가 / 제외” 결과 차이를 짧게 설명한다.

완료 기준:
- 포장 상품 1개는 최소 입력으로, 여러 재료 사진은 문제 항목만 확인해 등록할 수 있다.
- 뒤로가기·권한 거절·분석 실패·중복·기한 모름·저장 실패에서 초안이 사라지지 않는다.

#### D. 보관함 → 검색/필터 → 상세 → 소비/폐기/되돌리기

핵심 파일:
- apps/mobile/app/(tabs)/inventory.tsx
- apps/mobile/app/inventory/[id].tsx
- apps/mobile/src/features/inventory/*
- apps/mobile/src/components/InventoryCard.tsx
- apps/mobile/src/components/InventoryCleanupSheet.tsx

요구사항:
- 기본 보관함 상단은 공간 전환, 검색, 활성 필터 요약, 필터 버튼까지만 간결하게 보인다.
- 상태 4종, 위치, 초기화는 하나의 필터 시트에서 선택한다. 현재 선택 개수와 결과 건수를 CTA에
  보여주고, 홈에서 들어온 상태 필터도 같은 모델로 표현한다.
- 일괄 정리는 별도 모드로 진입시켜 일반 탐색 조작과 섞지 않는다. 선택 모드에서는 선택 수,
  전체/만료 선택, 취소, 실행만 남긴다.
- 목록 행은 이름, 위치·수량, 기한 상태, 빠른 정리 행동의 위계를 통일한다. 색은 상태를 보조할
  뿐 유일한 신호가 아니어야 한다.
- 상세는 읽기 상태를 기본으로 하고 편집은 명시적으로 진입한다. 소비·폐기는 같은 “정리” 계열로
  묶되 파괴성이 다른 것을 버튼 스타일과 확인 문구로 구분한다.
- 소비·폐기 직후 undo는 손이 닿는 곳에 충분히 머물고 스크린리더에 알린다. 네트워크 실패 시
  항목을 조용히 잃지 않고 원래 상태로 복구한다.

완료 기준:
- 첫 재료 카드가 과도한 필터 UI 아래로 밀리지 않는다.
- 필터 적용/해제, 일괄 폐기, 부분 소비, undo가 시각·접근성 양쪽에서 명확하다.

#### E. 추천 설정 → 결과 → 레시피 상세 → 요리 → 재고 반영

핵심 파일:
- apps/mobile/app/(tabs)/recommendations.tsx
- apps/mobile/src/features/recipes/*
- apps/mobile/src/features/recipes/recipe-detail-sheet.tsx
- apps/mobile/app/cooking/[recommendationId].tsx

요구사항:
- 추천 기본 화면은 `현재 조건 요약 → 추천 받기 → 결과` 흐름만 먼저 읽히게 한다.
- 재료·인원·시간·끼니·개인 설정은 하나의 설정 시트 안에서 그룹화하고, 적용한 핵심 조건을
  한 줄 요약으로 항상 보여준다.
- 최신 추천 결과를 최우선으로 두고 이전 추천은 접힌 기록 또는 별도 진입점으로 낮춘다.
  즐겨찾기는 현재 탭형 전환을 유지할 수 있지만 생성 CTA·결과·과금 제안과 경쟁하지 않게 한다.
- 광고 추천권, 구독, 유료 추천권은 한도 도달 시에만 맥락적으로 제시한다. 같은 화면에 여러
  판매 선택과 장고 히어로가 동시에 경쟁하지 않게 한다.
- 결과가 이미 있을 때도 “다시 추천”의 위치와 비용/추천권 영향을 예측할 수 있게 한다.
- 레시피 상세에서는 `요리 시작`이 primary다. 선택 재료, 빠진 재료, 조리 순서, 안전 팁은
  훑어보기 쉬운 섹션으로 정리하고 제휴 장보기는 보조 행동으로 둔다.
- 조리 중에는 현재 한 단계, 타이머, 이전/다음만 우선 노출한다. 전체 단계는 시트에서 보고,
  화면 꺼짐 방지·세션 복구·백그라운드 타이머 동작은 유지한다.
- 요리 완료 후에는 “사용량 확인 및 재고 반영”을 primary로 두고, 나중에 정리할 때 어떤 상태로
  남는지 명확히 설명한다.

완료 기준:
- 추천을 받기 전, 받은 후, 한도 도달, 생성 실패, 즐겨찾기, 재개한 요리의 주 행동이 각각 하나다.
- 추천부터 재고 반영까지 뒤로가기와 앱 재실행 후에도 맥락이 보존된다.

#### F. 공유 냉장고 생성/전환 → 초대 → 역할·알림 관리

핵심 파일:

- apps/mobile/app/settings/spaces/[spaceId].tsx
- apps/mobile/app/spaces/invitations/*.tsx
- apps/mobile/src/components/SpaceSwitcher.tsx

요구사항:
- 활성 냉장고 이름은 홈·보관함·추천·장보기에서 같은 위치와 표현으로 인지할 수 있게 한다.
- 공간 전환 직후 기존 공간 데이터가 잠깐 섞여 보이지 않게 기존 query gate를 유지하고,
  전환 중임을 skeleton/label로 명확히 표시한다.
- 공간 생성과 초대 참여를 분리한다. 초대 코드는 입력 → 공간·초대자 확인 → 참여 결과 순으로
  보여주고 로그인/가입이 필요해도 복귀 경로를 보존한다.
- 역할에 따라 불가능한 행동은 숨기기만 하지 말고, 사용자가 이유를 알아야 하는 문맥에서는
  읽기 전용 상태와 권한 설명을 제공한다.
- 구성원 제거, 나가기, 소유권 이전, 초대 취소는 대상·영향·되돌릴 수 없음 여부를 확인한다.
- 공간별 알림과 전체 알림의 관계를 한 화면에서 이해할 수 있게 설명한다.

완료 기준:
- 두 계정이 초대, 전환, 동기화, 권한 차이를 혼동 없이 완료할 수 있다.
- 계정 삭제가 공유 재고에 미치는 실제 정책을 UI가 정확히 설명한다.

#### G. 장보기 → 상품 탐색 → 외부 이동

요구사항:

- 상품 카드의 상품명, 가격, 배송/판매처 정보, 외부 이동 CTA 위계를 통일한다.
- 쿠팡 파트너스 고지는 첫 제휴 결과 가까이와 화면 하단에 법적 의미가 보존되도록 배치한다.
- 외부 링크임을 CTA와 접근성 힌트로 예측 가능하게 하되 불필요한 확인 모달은 추가하지 않는다.
- 검색 오류, 결과 없음, 기능 비활성, 최근 기록 없음은 서로 다른 다음 행동을 제공한다.
- 장보기 콘텐츠가 홈의 만료·임박 해결보다 더 강한 시각적 긴급성을 갖지 않게 한다.

완료 기준:
- 사용자가 왜 이 상품을 보는지, 누르면 어디로 가는지, 제휴 관계가 무엇인지 이해할 수 있다.

  파괴적 확인을 둔다. 장고의 걱정 표현이 공포나 guilt를 유도하지 않게 한다.

완료 기준:
- 가격·갱신·무료 기능 유지 여부가 결제 전에 보인다.
- 구독 취소와 계정 삭제가 서로 다른 행동임을 명확히 이해할 수 있다.

### 5. 공통 상태·피드백 규칙

- 초기 로딩은 레이아웃이 흔들리지 않는 skeleton을 사용한다. 처리 시간이 긴 AI 분석·추천은
  진행 중임과 앱을 떠나도 되는지 설명한다.
- 전체 실패는 `EmptyState + 다시 시도`, 일부 실패는 해당 섹션 안 `FeedbackBanner`, 짧은 완료는
  snackbar/inline confirmation을 기본으로 한다.
- `Alert.alert`는 OS 권한 안내, 되돌릴 수 없는 삭제/폐기, 앱 밖 결제·링크처럼 즉시 집중이 필요한
  경우에만 남긴다.
- 재시도는 사용자가 입력·선택·초안을 다시 만들게 하지 않는다.
- 같은 성공 메시지를 Alert, 배너, 장고 말풍선으로 중복 노출하지 않는다.
- disabled CTA에는 가능하면 바로 근처에 이유를 표시한다.
- 모든 비동기 CTA는 중복 탭을 막고, busy/disabled 상태를 접근성 API에도 전달한다.

### 6. 접근성·반응형 완료 조건

- 320~430pt 휴대폰, 작은 높이, 태블릿/폴더블, 세로·지원되는 가로 방향을 확인한다.
- Android 글자 크기 2.0과 표시 크기 확대에서 텍스트 잘림, 겹침, 가로 스크롤이 없어야 한다.
- 키보드가 마지막 입력과 sticky CTA를 가리지 않아야 한다.
- 모든 아이콘 버튼은 이름과 최소 44x44 터치 영역, 모든 일반 조작은 최소 48 높이를 갖는다.
- 선택·오류·성공·진행 상태는 색만으로 전달하지 않는다.
- 동적 갱신은 `accessibilityLiveRegion`, 선택/확장/비활성은 `accessibilityState`를 사용한다.
- 스크린리더 읽기 순서는 시각 순서와 일치하고, 장식 배경·중복 아이콘은 읽지 않게 한다.
- Reduce Motion에서 핵심 상태 변화가 사라지지 않아야 한다.

### 7. 구현 순서

다음 순서를 지키고 각 단계의 변경 파일을 제한하라.

1. P0-1: 공통 상태/CTA/피드백 패턴과 필요한 최소 컴포넌트 보완
2. P0-2: 홈 + 보관함 정보 구조 단순화
3. P0-3: 추천 + 레시피 상세 + 조리 완료 위계 정리
4. P0-4: 사진 검토의 문제 항목 우선·점진 공개
5. P1-1: 온보딩·인증 + 수동/스캐너 등록 마무리
6. P1-2: 공유 냉장고 + 설정 + 플러스 + 개인정보
7. P1-3: 장보기와 제휴 콘텐츠의 일관성·고지·빈 상태
8. P2: 모션, 미세 카피, 시각 polish

각 단계 시작 전에 다음을 보고하라.

- 바꾸려는 사용자 문제
- 수정할 파일
- 보존할 로직/계약
- 성공 여부를 확인할 시나리오와 화면 상태

### 9. 최종 보고 형식

완료 후 다음 순서로 짧고 구체적으로 보고하라.

“더 예뻐졌다”가 아니라 아래 지표로 결과를 평가하라.

- 첫 핵심 행동까지의 탭 수
- 한 화면에서 경쟁하는 주 CTA 수
- 입력/초안이 보존되는 실패 경로 비율
- 필터 전에 보이는 첫 콘텐츠 위치
- 추천 생성부터 요리 시작까지의 결정 수
- 최대 글자 크기에서의 잘림/겹침 0건
- 색만으로 전달되는 상태 0건
- 기존 핵심 testID·analytics event 유실 0건
```

## 권장 사용법

한 번에 전체 프롬프트를 실행하되 구현은 반드시 `구현 순서`의 한 단계씩 끊는다. 첫 응답에서는
코드 수정 없이 UX 감사와 P0 범위만 받는 편이 안전하다. 이후 같은 대화에서 다음처럼 진행한다.

```text
감사 결과의 P0-1만 구현해줘. 범위 밖 파일은 수정하지 말고, 완료 후 테스트와 변경 전/후 상태를
보고한 뒤 멈춰줘.
```
