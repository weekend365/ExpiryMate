# 홈 빠른 동작 UX 개선안

## 목적

홈에서 재료 등록을 시작해 냉장고에 반영하기까지의 시간을 줄이고, 사용자가 등록
방식을 고르는 과정에서 겪는 탐색과 중복 확인을 줄인다.

이 문서는 2026-08-28 모바일 구현을 기준으로 한 UX 검토 결과다. 실제 사용성 테스트
결과가 아니라 코드와 화면 구조를 바탕으로 한 개선 가설이며, 구현 전 와이어프레임과
사용성 테스트로 우선순위를 검증한다.

검토 대상:

- 홈 빠른 동작: [`home-quick-entry.tsx`](../../apps/mobile/src/features/home/home-quick-entry.tsx)
- 홈 내 배치: `apps/mobile/app/(tabs)/home.tsx`
- 직접 등록: [`register.tsx`](../../apps/mobile/app/register.tsx)
- 바코드 등록: [`scanner-camera.tsx`](../../apps/mobile/src/features/scanner/scanner-camera.tsx),
  [`scanner-confirm-sheet.tsx`](../../apps/mobile/src/features/scanner/scanner-confirm-sheet.tsx)
- 사진 일괄 등록: [`register-photo.tsx`](../../apps/mobile/app/register-photo.tsx)

## 현재 사용자 흐름

| 시작 동작 | 주요 흐름 | 관찰한 마찰 |
|---|---|---|
| 바코드 스캔 | 홈 → 바코드 촬영 → 유통기한 촬영 → 결과 확인 → 수량 → 기한 재확인 → 완료 | 이미 스캔한 기한을 일반 등록 단계에서 다시 확인해야 함 |
| 직접 입력 | 홈 → 재료명 → 수량·보관 위치 → 유통기한 → 완료 | 단계는 명확하지만 홈에서 진입점을 찾기 위해 스크롤할 수 있음 |
| 사진으로 넣기 | 홈 → 사진 종류 → 촬영/앨범 선택 → 분석 → 여러 재료 검수 → 완료 | 사진 선택 전 결정이 분산되고, 이용 가능 횟수·광고 안내가 중간에 나타날 수 있음 |
| 장보기 | 홈 → 검색 또는 최근 소진 재료 → 외부 상품 선택 | 재료 등록 동작과 목적이 다르지만 같은 빠른 동작 그룹에 있음 |

## 개선점 1. 빠른 동작의 위치와 정보 구조 재편

### 문제

빠른 동작은 홈의 요리 추천과 유통기한 현황 다음에 있다. 작은 화면이나 큰 글자
환경에서는 핵심 등록 진입점이 첫 화면 밖으로 밀릴 가능성이 높다. 또한 `바코드 스캔`,
`직접 입력`, `사진으로 넣기`는 재료 등록 방식인 반면 `장보기`는 구매 목적이어서 같은
계층에 놓이면 빠른 동작의 의미가 흐려진다.

재고가 없을 때 버튼 크기만 키우는 현재 방식은 발견성을 일부 높이지만, 위치가 바뀌지
않아 반복 사용자의 근육 기억을 만들기 어렵다.

### 권장안

1. 홈 첫 화면 또는 하단 내비게이터에 가까운 엄지 영역에 주요 CTA `재료 넣기`를 항상
   같은 위치로 제공한다.
2. CTA를 누르면 바텀시트에서 `바코드`, `직접 입력`, `사진으로 여러 개`를 선택하게 한다.
3. 가장 빈도가 높은 바코드를 Primary로 표현하고 나머지는 동등한 Secondary 선택지로
   둔다.
4. `장보기`는 빠른 등록 그룹에서 분리해 `최근 다 쓴 재료 다시 사기`처럼 구매 맥락이
   드러나는 별도 카드나 섹션으로 이동한다.
5. 기존 개별 경로와 접근성 레이블은 유지해 보조 기술 사용자에게 선택 단계가 추가되지
   않도록 한다.

### 인수 기준

- `small-three-button`과 `small-large-text` 레이아웃에서 스크롤 없이 `재료 넣기`를 찾고
  실행할 수 있다.
- 주요 CTA는 `touchTarget.cta` 이상이며 하단 내비게이터와 안전 영역을 침범하지 않는다.
- 바텀시트에는 등록 방식만 표시하며 Primary CTA는 하나다.
- 장보기는 등록 방식과 시각적으로 분리되고, 기존 장보기 화면으로 이동할 수 있다.

### 확인 지표

- 홈 노출 대비 재료 등록 시작률
- 홈 진입부터 등록 방식 선택까지 걸린 시간
- 빠른 동작 영역의 오탭 및 즉시 뒤로 가기 비율

## 개선점 2. 바코드 결과에서 바로 넣을 수 있는 빠른 완료 경로 제공

### 문제

현재 스캐너는 바코드와 유통기한을 확인한 뒤 `양만 맞출게요`를 통해 일반 등록 화면으로
이동한다. 스캔 결과에 유통기한이 포함되어 있어도 사용자는 수량 단계와 기한 단계를 다시
거쳐야 한다. 빠른 동작으로 시작했지만 일반 등록 흐름이 이어져 완료까지의 결정 횟수가
많다.

### 권장안

1. 스캔 결과 시트에 상품명, 수량, 보관 위치, 유통기한의 요약을 보여 준다.
2. 수량은 `1`, 보관 위치는 최근 사용 위치, 유통기한은 스캔 결과를 기본값으로 사용한다.
3. 결과가 완전하면 Primary CTA를 `냉장고에 넣을게요`로 제공해 시트에서 바로 완료한다.
4. 기본값이 맞지 않을 때만 수량 스테퍼와 보관 위치 칩으로 빠르게 조정한다.
5. 상품명, 단위, 추가 정보 등 전체 수정은 `자세히 고칠게요`를 통해 기존 단계형 등록
   화면으로 넘긴다.
6. 완료 화면의 Primary CTA는 같은 방식으로 다음 재료를 스캔하게 하고, 중단과 상세 수정
   경로도 유지한다.

### 인수 기준

- 상품명과 유통기한이 정상 인식된 경우 일반 등록 화면을 거치지 않고 저장할 수 있다.
- 자동 입력한 값은 저장 전에 읽을 수 있으며, 사용자가 수정 또는 전체 편집을 선택할 수
  있다.
- 이름이나 유통기한이 없거나 신뢰할 수 없는 경우에는 기존 보완 단계로 안전하게
  전환한다.
- 저장 진행, 성공, 실패, 재시도 상태를 같은 맥락에서 명확하게 안내한다.
- 연속 스캔과 `그만 추가할래요` 경로가 모두 유지된다.

### 확인 지표

- 바코드 시작부터 첫 재료 완료까지 걸린 시간
- 스캔 결과 확인 후 일반 등록 화면으로 이동하는 비율
- 스캔 결과 확인 단계와 수량·기한 단계의 이탈률
- 자동 입력값 수정률과 저장 후 상세 수정률

## 개선점 3. 사진 등록의 선행 선택과 이용 조건 통합

### 문제

사진 등록은 사진 종류, 카메라 또는 앨범, AI 안내 동의, 이용 가능 횟수 또는 광고,
운영체제 선택기로 결정 지점이 나뉜다. 사용자는 등록을 시작한 뒤에야 추가 조건을 발견할
수 있고, 이는 `사진으로 넣기`가 주는 빠른 일괄 등록 기대와 어긋날 수 있다.

### 권장안

1. 사진 등록 진입 직후 한 번의 선택 화면에서 `영수증 촬영`, `냉장고 촬영`, `앨범에서
   가져오기`를 제공한다. 각 항목은 “구매 목록을 한 번에”, “보이는 재료를 여러 개”처럼
   예상 결과를 한 줄로 설명한다.
2. 무료 분석 가능 여부, 남은 횟수, 광고 필요 여부를 사진 선택 전에 같은 화면에서
   알린다.
3. AI 데이터 안내 동의가 필요하면 선택 직후 안내하고, 동의 후 사용자가 고른 촬영
   방식으로 돌아온다.
4. 최근 사용한 사진 종류와 출처를 기억하되 자동 실행하지 않고 추천 선택지로 표시한다.
5. 분석 이후에는 현재의 보관 위치·유통기한 일괄 적용을 유지하고, 누락되거나 신뢰도가
   낮은 항목만 우선적으로 강조한다.

### 인수 기준

- 사용자는 사진 또는 카메라를 열기 전에 사진 유형, 예상 결과, 이용 조건을 알 수 있다.
- 하나의 선택으로 사진 유형과 입력 출처가 결정되며 불필요한 중간 화면을 거치지 않는다.
- 동의, 권한 거절, 분석권 부족, 광고 실패 상태마다 직접 등록으로 전환하거나 이전 선택을
  유지한 채 재시도할 수 있다.
- 일괄 적용 후에도 개별 재료의 이름, 수량, 위치, 기한을 수정하거나 제외할 수 있다.
- 분석 결과가 없을 때 다른 사진과 직접 등록 경로를 모두 제공한다.

### 확인 지표

- 사진 등록 진입부터 운영체제 사진 선택기 실행까지 걸린 시간
- 사진 종류 및 출처 선택 단계의 이탈률
- 광고 또는 AI 안내 노출 후 등록 포기율
- 분석 성공 후 일괄 저장 완료율과 항목별 수정률

## 권장 우선순위

1. **P0 — 빠른 동작 위치와 정보 구조 재편:** 모든 등록 방식의 발견성에 영향을 준다.
2. **P0 — 바코드 빠른 완료 경로:** 반복 빈도가 높은 단건 등록의 완료 시간을 직접 줄인다.
3. **P1 — 사진 등록 선택 통합:** 일괄 등록의 기대와 실제 흐름을 맞추고 중간 이탈을 줄인다.

## 검증 계획

1. 세 개선안의 저해상도 와이어프레임을 만들고 기존 화면과 비교한다.
2. 신규 사용자와 반복 사용자 각각 최소 3명에게 `우유 한 개 등록`, `영수증으로 여러 개
   등록`, `최근 다 쓴 재료 구매` 과제를 수행하게 한다.
3. 완료 시간, 되돌아가기 횟수, 도움 요청, 과제 성공 여부를 기록한다.
4. `small-three-button`, `modern-gesture`, `small-large-text`, 태블릿 프로필에서 레이아웃과
   동적 글자 크기를 확인한다.
5. 지표 기준선을 먼저 수집한 뒤 단계별로 배포해 개선 전후를 비교한다.

## 범위 밖

- 바코드·OCR 인식 정확도 개선
- 상품 카탈로그 데이터 품질 개선
- 사진 분석 과금 및 광고 정책 변경
- 장보기 제휴사와 외부 결제 흐름 변경
